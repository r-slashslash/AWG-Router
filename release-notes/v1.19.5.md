## What's changed

- **Let's Encrypt through a web server on port 80 works.** Since 1.14.0 the panel put its test file in the wrong folder, so validation through nginx, Apache or Caddy always failed with HTTP 404 and was rolled back. If port 80 on your server is taken by a web server, open **System → Domain and certificate** after the update and set up the validation again. Thanks to @xiaomiiraqly-alt (#21).

- **Exits at an IPv6 address.** In the AmneziaVPN container mode Docker gives the container no IPv6 by default, so such an exit just showed "no connection". Now it says why and what to do: turn on IPv6 in Docker (README, "Limitations") or give the exit an IPv4 address or a domain with an A record. If IPv6 in Docker is already on, nothing changes. Thanks to @paris19891 (#20).

- **Server public address.** This field is also the address the panel opens at and the name in its certificate, and the panel listens on IPv4 only. It no longer takes an IPv6 address, and its hint now says so. To have clients connect over IPv6, pick the address in **Address in configs**. If an IPv6 address was saved in the field, it moves there by itself. Thanks to @paris19891 (#20).

## Update

**System → Update** in the panel (since 1.4.0), or on the server:

    awg-router update

New install (Ubuntu or Debian, as root):

    curl -fsSL https://raw.githubusercontent.com/r-slashslash/AWG-Router/main/install.sh | bash

## Что изменилось

- **Let's Encrypt через веб-сервер на порту 80 работает.** С версии 1.14.0 панель клала проверочный файл не в ту папку, поэтому проверка через nginx, Apache или Caddy всегда заканчивалась ошибкой HTTP 404 и откатывалась. Если порт 80 на вашем сервере занят веб-сервером, после обновления откройте **«Система» → «Домен и сертификат»** и настройте проверку ещё раз. Спасибо @xiaomiiraqly-alt (#21).

- **Выходы с адресом IPv6.** В режиме контейнера AmneziaVPN Docker по умолчанию не даёт контейнеру IPv6, и такой выход просто показывал «нет связи». Теперь он пишет причину и что делать: включить IPv6 в Docker (README, «Ограничения») или указать у выхода IPv4-адрес либо домен с записью A. Если IPv6 в Docker уже включён, ничего не меняется. Спасибо @paris19891 (#20).

- **Внешний адрес сервера.** Это поле — ещё и адрес, по которому открывается панель, и имя в её сертификате, а панель слушает только IPv4. Адрес IPv6 оно больше не принимает, и подсказка теперь это объясняет. Чтобы клиенты подключались по IPv6, выберите адрес в **«Адрес в конфигах»**. Если в поле был сохранён адрес IPv6, он переедет туда сам. Спасибо @paris19891 (#20).

## 改动

- **通过 80 端口上的 Web 服务器进行 Let's Encrypt 验证现已可用。** 从 1.14.0 起，面板把验证文件放错了目录，所以通过 nginx、Apache 或 Caddy 的验证总是以 HTTP 404 失败并被回滚。如果服务器的 80 端口被 Web 服务器占用，更新后请打开 **系统 → 域名和证书**，重新设置验证。感谢 @xiaomiiraqly-alt（#21）。

- **使用 IPv6 地址的出口。** 在 AmneziaVPN 容器模式下，Docker 默认不给容器分配 IPv6，这样的出口只会显示“无连接”。现在它会说明原因和解决办法：在 Docker 中启用 IPv6（见 README“限制”一节），或为出口改用 IPv4 地址或带 A 记录的域名。如果 Docker 已启用 IPv6，则一切照旧。感谢 @paris19891（#20）。

- **服务器公网地址。** 这个字段同时也是面板的访问地址和证书中的名称，而面板只监听 IPv4。它不再接受 IPv6 地址，提示中也说明了这一点。要让客户端通过 IPv6 连接，请在 **配置中的地址** 中选择该地址。如果该字段中已保存了 IPv6 地址，它会自动移到那里。感谢 @paris19891（#20）。

## تغییرها

- **اعتبارسنجی Let's Encrypt از راه وب‌سرور روی درگاه 80 کار می‌کند.** از نسخهٔ 1.14.0 پنل فایل آزمایشی را در پوشهٔ اشتباه می‌گذاشت، برای همین اعتبارسنجی از راه nginx، Apache یا Caddy همیشه با خطای <bdi>HTTP 404</bdi> شکست می‌خورد و برگردانده می‌شد. اگر درگاه 80 سرور شما را وب‌سرور گرفته است، پس از به‌روزرسانی **سیستم ← دامنه و گواهی** را باز کنید و اعتبارسنجی را دوباره تنظیم کنید. سپاس از <bdi>@xiaomiiraqly-alt</bdi> (<bdi>#21</bdi>).

- **خروجی با نشانی IPv6.** در حالت کانتینر AmneziaVPN، Docker به‌طور پیش‌فرض به کانتینر IPv6 نمی‌دهد و چنین خروجی‌ای فقط «بدون اتصال» نشان می‌داد. اکنون علت و راه‌حل را می‌گوید: IPv6 را در Docker روشن کنید (README، بخش «محدودیت‌ها») یا برای خروجی نشانی IPv4 یا دامنه‌ای با رکورد A بدهید. اگر IPv6 در Docker از قبل روشن است، چیزی تغییر نمی‌کند. سپاس از <bdi>@paris19891</bdi> (<bdi>#20</bdi>).

- **آدرس عمومی سرور.** این فیلد نشانی‌ای است که پنل با آن باز می‌شود و نام درون گواهی آن هم هست، و پنل فقط روی IPv4 گوش می‌دهد. دیگر نشانی IPv6 را نمی‌پذیرد و راهنمای آن هم همین را می‌گوید. برای اتصال کلاینت‌ها با IPv6، نشانی را در **آدرس در پیکربندی‌ها** انتخاب کنید. اگر در این فیلد نشانی IPv6 ذخیره شده بود، خودش به آنجا منتقل می‌شود. سپاس از <bdi>@paris19891</bdi> (<bdi>#20</bdi>).
