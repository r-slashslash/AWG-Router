## What's changed

- **Important if DNS on the server is on and your server is in Russia, China or Iran.** The panel no longer falls back to the country's DNS by itself: after the update **Server → DNS → Fallback DNS for "Direct"** is off. If some clients go **Direct**, turn it on and enter the country's DNS, for example `77.88.8.8`. When the DNS servers don't answer from your server (encrypted DNS is often cut there), names of sites that go **Direct** are asked there instead — from the same outgoing address. **Apply for Russia / China / Iran** fills it in and turns it on.

- **Safer**: the panel's own AmneziaWG container no longer runs with full host rights; clients can't reach Alibaba Cloud's service address `100.100.100.200` (like `169.254.169.254`); after a reboot clients' IPv6 is closed until the panel starts; password guessing from one hosting network is limited too; the installer checks Docker Compose and buildx against fixed checksums.

- **Several outgoing addresses.** If your server has more than one IPv4 address, add the others in **Server → Additional outgoing addresses** — copy them from your hosting panel (on AWS, the internal second address). The panel adds them to the server's system itself and checks what websites see from each. Then every exit choice has **Direct** per address (**Direct — 198.51.100.7**), main one first: a rule, a client or Default can go out to the internet from its own address. An exit through another server can connect from one of them too (**Connect from address** in its window), and the other server sees that address. **Server outgoing address** picks the main one.

- **An outgoing address that stops working never lets traffic out from another one.** What goes through it is blocked, its card turns red, exit choices mark it "not working", an exit connecting from it switches to its fallback, and Telegram tells you when it stops and when it works again.

- **Routing → Server addresses.** A new block shows the server's incoming addresses (how many clients have each in their config) and outgoing ones (what websites see from each and where it is used). Tap an address to tick clients, rules and exits that should use it; untick — back to the main address. **Route check** shows the address too.

- **Changing the main outgoing address moves** everything on plain **Direct** to the new one. Before saving, the panel shows what moves, where removed addresses are used (they go to the main one) and which clients need a new config.

- **Open connections follow your changes.** When you change an exit by hand (routing, a client, an exit, an address), only the connections whose path changed are closed, and apps reconnect over the new path. Load balancing and fallbacks still don't drop anything.

- **The panel address and the clients' address are now separate.** **Server incoming address** (in client configs) and **Additional incoming addresses** replace **Server public address** and **Address in configs**; everything you had stays as it was. The address the panel opens at is now **System → Panel address**, and changing it doesn't touch clients.

- **The server's own connections** — panel updates, lists, the certificate — can go out from a chosen address: **System → Address the server itself goes out from**. If that address stops working, the server goes back to the system address, so it isn't left without updates.

- **A rule's own DNS and the fallback DNS can be encrypted**: `https://…/dns-query` for DoH, `h3://…/dns-query` for DoH over HTTP/3 only, `tls://…` for DoT, for example `tls://common.dot.dns.yandex.net`. Each is asked exactly the way it is written. HTTP/3 goes over UDP and an ISP may cut it apart from HTTPS — put `https://` as the second entry.

- **DNS on the server now answers every DNS query of the clients**, also the second DNS in their configs and a DNS typed into a device or an app: names no longer go past the exit or unencrypted, and configs issued earlier don't need to be imported again. While the panel restarts or updates, names don't resolve for a few seconds.

- **ARM servers** (Oracle Free, Hetzner ARM): the AmneziaWG server image is now built for arm64 too — before, the VPN in its own container didn't start there at all. If a ready image doesn't fit the server's processor, the installer builds it on the server.

- **DoH now speaks HTTP/2**: Quad9 and Yandex stopped answering DoH over HTTP/1.1, so with them it didn't work at all — including Quad9 in the DNS servers with the default DoH encryption.

- Encrypted DNS on the server answers 40–150 ms faster per query.

- **One slow site no longer switches everyone to the fallback DNS.** One name the DNS servers didn't answer in time (the site's own name servers don't respond) or one lost packet counted as "the DNS servers don't answer": for 2 minutes all **Direct** clients asked the country's DNS instead, unencrypted. Now the panel first checks the DNS servers (a fraction of a second when they answer); where encrypted DNS is really cut, the fallback takes over as fast as before.

- **DNS on the server under load.** On a busy server a burst of names could still switch all **Direct** clients to the fallback DNS for 2 minutes, and some names got no answer; and while one device kept asking a name that doesn't answer, every new site on **Direct** opened a few seconds late for everyone. Both are fixed.

- **Route check** resolves a domain through the client's exit again, as it should: since 1.21.0 it asked the server's own DNS, which in Russia, China or Iran may give a spoofed address.

- **Fewer ways past an exit and fewer stuck states**: with **Domain rules only for addresses from this DNS's answers**, the first connection to a new address of a site from a rule no longer goes past the exit; a full-tunnel WireGuard on the same server (wg-quick, for example WARP) no longer lets clients' UDP past the exit and past **Block**; a lost SSH session during `awg-router update` no longer leaves the VPN off; one exit stuck in amneziawg-go no longer stops the panel from applying rules — its clients go to its fallback; backups over 4 MB restore; domain rules keep working when the panel changes their settings right after a start.

- Restoring a backup on another server: addresses belong to each server and aren't copied; where the backup used an address this server doesn't have, the main one is used, and the panel says where.

- The Telegram bot shows "direct — address" where a client goes out from a non-main address.

- Pressing **Apply for …** again now makes the country's rules what the first press made — Direct, on, with the country's current DNS, at the end (speed and monthly limits stay).

- The fallback DNS: a name that was waiting while you changed or turned off the fallback goes to the new one; "The fallback DNS doesn't answer either" no longer stays on the **Server** tab for up to 15 minutes after everything works; a fallback written by name (`tls://…`) works on **Direct — address** when the DNS servers there are unencrypted and don't answer.

- A device that checks DNSSEC itself (for example, Linux with `DNSSEC=yes`) no longer gets an answer without signatures from the DNS cache when another device asked the same site first.

- Client speeds come only with the **Clients** tab (a few seconds after opening it): the other tabs ask the server for less.

- lego, the program that gets the HTTPS certificate, is updated to 5.7.0 (#55).

- **Server → DNS** is tidier: encryption comes right under **DNS on the server**, then the fallback DNS.

- Hints in the panel are shorter and clearer.

- **No more browser pop-ups**: the panel asks in its own bar at the top or at the bottom of the window. Under a field whose change needs new client configs, the panel says so in orange. **System → Domain and certificate** is now **Certificate settings**, and **Get a certificate now** is in that window.

- Smaller interface fixes: a message no longer covers **Save** and **Cancel** of a window on a phone (it is at the top and closes on tap), the rule window fits a phone screen, links like `vpn://` read the right way in Persian, typed but unsaved fields stay after a window closes, error messages are more precise, warnings and the buttons of the dark theme have more contrast.

New install (Ubuntu or Debian, as root):

If you save anything on **Routing** in 1.24.0, its rules lose **Direct — address** and the DoH/DoT entries of their own DNS: after coming back to 1.25.0 they are plain **Direct** and keep only the plain DNS addresses.

- **Важно, если включён DNS на сервере и сервер в России, Китае или Иране.** Панель больше не переходит на DNS страны сама: после обновления **«Сервер» → «DNS» → «Запасной DNS для «Напрямую»»** выключен. Тогда в каждом выборе выхода у каждого адреса своё **«Напрямую»** (**«Напрямую — 198.51.100.7»**), основной первым: правило, клиент или «По умолчанию» могут выходить в интернет со своего адреса. Выход через другой сервер тоже может подключаться с одного из них (**«Подключаться с адреса»** в его окне) — второй сервер увидит этот адрес. **«Исходящий адрес сервера»** выбирает основной.

- **Исходящий адрес, который перестал работать, никогда не выпускает трафик с другого.** Всё, что шло через него, блокируется, его карточка становится красной, в выборе выхода он помечен «не работает», выход, который с него подключается, переходит на свой резерв, а Telegram сообщает, когда адрес перестал и когда снова начал работать.

- **«Маршрутизация» → «Адреса сервера».** Новый блок показывает входящие адреса сервера (у скольких клиентов каждый в конфиге) и исходящие (что с каждого видят сайты и где он стоит). Нажмите на адрес, чтобы отметить клиентов, правила и выходы, которым он нужен; снятая галочка — снова основной адрес. **«Проверка маршрута»** тоже показывает адрес.

- **Смена основного исходящего адреса — это переезд** всего, что стоит просто на **«Напрямую»**, на новый адрес. Перед сохранением панель покажет, что переедет, где стоят убранные адреса (там будет основной) и каким клиентам нужен новый конфиг.

Адрес, по которому открывается панель, теперь — **«Система» → «Адрес панели»**, и его смена клиентов не трогает.

- **Свой DNS правила и запасной DNS могут быть шифрованными**: `https://…/dns-query` — DoH, `h3://…/dns-query` — DoH только по HTTP/3, `tls://…` — DoT, например `tls://common.dot.dns.yandex.net`. - **DNS на сервере теперь отвечает на все запросы DNS клиентов** — и на второй DNS из их конфигов, и на DNS, вписанный в устройство или приложение: имена больше не уходят мимо выхода и без шифрования, а конфиги, выданные раньше, перекачивать не нужно. Пока панель перезапускается или обновляется, имена несколько секунд не разрешаются.

- **Серверы на ARM** (Oracle Free, Hetzner ARM): образ сервера AmneziaWG теперь собирается и для arm64 — раньше VPN в своём контейнере там не запускался совсем. Если готовый образ не подходит процессору сервера, установщик соберёт его на сервере.

- **DoH теперь работает по HTTP/2**: Quad9 и Яндекс перестали отвечать на DoH по HTTP/1.1, и с ними он не работал совсем — в том числе Quad9 в серверах DNS с шифрованием DoH по умолчанию.

- Шифрованный DNS на сервере отвечает на 40–150 мс быстрее на каждый запрос.

- **Одно медленное имя больше не переключает всех на запасной DNS.** Одно имя, на которое серверы DNS не успели ответить (у сайта молчат его собственные серверы имён), или один потерянный пакет считались «серверы DNS не отвечают»: 2 минуты все клиенты **«Напрямую»** спрашивали DNS страны, без шифрования. Теперь панель сначала проверяет серверы DNS (когда они отвечают — за доли секунды); там, где шифрованный DNS правда режут, запасной включается так же быстро, как раньше.

- **DNS на сервере под нагрузкой.** На загруженном сервере всплеск имён ещё мог на 2 минуты перевести всех клиентов **«Напрямую»** на запасной DNS, и часть имён оставалась без ответа; а пока одно устройство снова и снова спрашивало имя, которое не отвечает, каждый новый сайт у всех **«Напрямую»** открывался на несколько секунд позже. Обе ошибки исправлены.

- **«Проверка маршрута»** снова узнаёт адрес домена через выход клиента, как и задумано: с 1.21.0 она спрашивала DNS самого сервера, а он в России, Китае или Иране может подменить адрес.

- **Меньше путей мимо выхода и зависаний**: с галочкой **«Правила по доменам — только для адресов из ответов этого DNS»** первое соединение к новому адресу сайта из правила больше не идёт мимо выхода; обычный WireGuard на том же сервере со всем трафиком через себя (wg-quick, например WARP) больше не пускает UDP клиентов мимо выхода и мимо **«Блокировать»**; обрыв SSH во время `awg-router update` больше не оставляет VPN выключенным; один зависший amneziawg-go выхода больше не мешает панели применять правила — его клиенты идут на резерв; восстанавливаются копии больше 4 МБ; правила по доменам не останавливаются, когда панель меняет их настройки сразу после запуска.

- Восстановление резервной копии на другом сервере: адреса у каждого сервера свои и не переносятся; где копия использовала адрес, которого у этого сервера нет, будет основной, и панель скажет где.

- Бот в Telegram показывает «напрямую — адрес», когда клиент выходит не с основного адреса.

- Повторное нажатие **«Применить для …»** теперь снова делает правила страны как при первом — «Напрямую», включены, с нынешним DNS страны, в конце (ограничения скорости и месячные лимиты остаются).

- Запасной DNS: имя, которое ждало ответа, пока вы меняли или выключали запасной, уходит к новому; «Запасной DNS тоже не отвечает» больше не висит на вкладке **«Сервер»** до 15 минут после того, как всё заработало; запасной, вписанный именем (`tls://…`), работает на **«Напрямую — адрес»**, когда серверы DNS там без шифрования и не отвечают.

- Устройство, которое само проверяет DNSSEC (например, Linux с `DNSSEC=yes`), больше не получает из кэша DNS ответ без подписей, если тот же сайт первым спросило другое устройство.

- Скорость клиентов приходит только на вкладке **«Клиенты»** (через несколько секунд после перехода): остальные вкладки спрашивают у сервера меньше.

- lego — программа, которая получает сертификат HTTPS, — обновлена до 5.7.0 (#55).

- **«Сервер» → «DNS»** стал проще: шифрование — сразу под **«DNS на сервере»**, за ним запасной DNS.

- Подсказки в панели стали короче и понятнее.

- **Окон браузера больше нет**: панель спрашивает своей полосой сверху или внизу окна. Под полем, после изменения которого клиентам нужны новые конфиги, панель пишет это оранжевым. **«Система» → «Домен и сертификат»** теперь **«Настройка сертификата»**, кнопка **«Получить сертификат сейчас»** — в этом окне.

- Мелкие исправления интерфейса: сообщение больше не закрывает **«Сохранить»** и **«Отмена»** окна на телефоне (оно сверху и закрывается нажатием), окно правила помещается на экран телефона, ссылки вида `vpn://` в персидском читаются правильно, набранное и не сохранённое в полях остаётся после закрытия окна, сообщения об ошибках точнее, у предупреждений и кнопок тёмной темы выше контраст.

- **重要：如果启用了服务器上的 DNS，且服务器位于俄罗斯、中国或伊朗。** 面板不再自动改用该国的 DNS：更新后 **服务器 → DNS → 「直连」的备用 DNS** 是关闭的。如果有客户端走 **直连**，请开启它并填入该国的 DNS，例如 `223.5.5.5`。当 DNS 服务器从你的服务器无法响应时（那里加密 DNS 常被阻断），**直连** 网站的名称改向它查询——从同一出站地址发出。**应用于俄罗斯 / 中国 / 伊朗** 会填入并开启它。

- **更安全**：面板自己的 AmneziaWG 容器不再以主机的全部权限运行；客户端无法访问阿里云的服务地址 `100.100.100.200`（与 `169.254.169.254` 一样）；重启后，在面板启动之前客户端的 IPv6 处于关闭状态；来自同一主机商网络的密码猜测也受到限制；安装程序按固定的校验和核对 Docker Compose 和 buildx。

- **多个出站地址。** 如果你的服务器有不止一个 IPv4 地址，请在 **服务器 → 附加出站地址** 中添加其他地址——从主机商面板复制（在 AWS 上填写内部的第二个地址）。面板会自动把它们添加到服务器系统中，并检查网站从每个地址看到的是什么。之后每个出口选择中，每个地址都有自己的 **直连**（**直连 — 198.51.100.7**），主地址排在最前：规则、客户端或默认出口都可以从自己的地址访问互联网。经其他服务器的出口也可以从其中一个地址连接（出口窗口中的 **从此地址连接**），另一台服务器看到的就是这个地址。**服务器出站地址** 用于选择主地址。

- **出站地址不可用时，绝不会让流量从其他地址出去。** 经过它的流量会被阻止，它的卡片变红，出口列表中标为「不可用」，从它连接的出口切换到自己的备用出口，并通过 Telegram 通知地址何时不可用、何时恢复。

- **路由 → 服务器地址。** 新区块显示服务器的入站地址（每个地址写在多少个客户端的配置中）和出站地址（网站从每个地址看到什么，以及它用在哪里）。点击地址即可勾选应使用它的客户端、规则和出口；取消勾选——回到主地址。**路由检测** 也会显示地址。

- **更换主出站地址就是迁移**：所有只选了 **直连** 的地方都会迁移到新地址。保存前，面板会显示哪些会迁移、被删除的地址用在哪里（那里将改用主地址），以及哪些客户端需要新配置。

- **已打开的连接会跟随你的改动。** 手动更改出口时（路由、客户端、出口、地址），只关闭路径发生变化的连接，应用会按新路径重新连接。负载均衡和备用出口仍然不会断开任何连接。

- **面板地址和客户端地址现在分开了。** **服务器入站地址**（写在客户端配置中）和 **附加入站地址** 取代了 **服务器公网地址** 和 **配置中的地址**；原有设置保持不变。打开面板的地址现在在 **系统 → 面板地址**，修改它不会影响客户端。

- **服务器自身的连接**——面板更新、列表、证书——可以从选定的地址访问外网：**系统 → 服务器自身从哪个地址访问外网**。如果该地址不可用，服务器会回到系统地址，以免收不到更新。

- **规则的专用 DNS 和备用 DNS 可以加密**：DoH 写 `https://…/dns-query`，仅通过 HTTP/3 的 DoH 写 `h3://…/dns-query`，DoT 写 `tls://…`，例如 `https://dns.alidns.com/dns-query`。每个都严格按所写的方式查询。HTTP/3 走 UDP，运营商可能单独阻断——第二个地址请填 `https://`。

- **服务器上的 DNS 现在应答客户端的所有 DNS 查询**——包括配置中的第二个 DNS 以及在设备或应用中手动填写的 DNS：域名不再绕过出口或以明文发出，之前发放的配置也无需重新导入。面板重启或更新时，域名会有几秒无法解析。

- **ARM 服务器**（Oracle Free、Hetzner ARM）：AmneziaWG 服务器镜像现在也为 arm64 构建——以前 VPN 在自己的容器中根本无法启动。如果现成镜像不适合服务器的处理器，安装程序会在服务器上构建。

- **DoH 现在支持 HTTP/2**：Quad9 和 Yandex 已不再响应 HTTP/1.1 的 DoH，之前与它们的 DoH 完全无法使用——包括在 DNS 服务器中填写 Quad9 并使用默认 DoH 加密的情况。

- 服务器上的加密 DNS 每次查询快 40–150 毫秒。

- **一个慢的网站不再让所有人改用备用 DNS。** 以前，DNS 服务器来不及回答的一个域名（该网站自己的域名服务器不响应）或一个丢失的数据包，都会被当作「DNS 服务器无响应」：2 分钟内所有 **直连** 客户端都改问该国的 DNS，且不加密。现在面板会先检查 DNS 服务器（服务器有响应时只需不到一秒）；在加密 DNS 确实被阻断的地方，备用 DNS 仍像以前一样迅速接管。

- **负载下的服务器 DNS。** 在繁忙的服务器上，一阵突发的域名查询仍可能让所有 **直连** 客户端改用备用 DNS 2 分钟，部分域名得不到应答；而当某台设备反复查询一个没有应答的域名时，所有 **直连** 用户打开每个新网站都会晚几秒。这两个问题都已修复。

- **路由检测** 重新经由客户端的出口解析域名，本应如此：自 1.21.0 起它询问的是服务器自身的 DNS，而在俄罗斯、中国或伊朗，它可能返回被篡改的地址。

- **更少的绕过出口和卡死情况**：勾选 **域名规则只针对此 DNS 应答中的地址** 时，连向规则中网站新地址的第一个连接不再绕过出口；同一服务器上让全部流量经过自己的普通 WireGuard（wg-quick，例如 WARP）不再让客户端的 UDP 绕过出口和 **阻止**；`awg-router update` 期间 SSH 断开不再让 VPN 保持关闭；某个出口的 amneziawg-go 卡死不再妨碍面板应用规则——其客户端改走备用出口；超过 4 MB 的备份可以恢复；面板在启动后立即修改域名规则的设置时，域名规则不再停止工作。

- 在另一台服务器上恢复备份：地址属于各自的服务器，不会被复制；备份中使用了本服务器没有的地址的地方会改用主地址，面板会说明是哪些地方。

- 当客户端不是从主地址访问外网时，Telegram 机器人显示「直连 — 地址」。

- 再次点击 **应用于 …** 现在会让该国的规则恢复为首次点击时的样子——直连、启用、使用该国当前的 DNS、位于末尾（速度限制和月度限额保留）。

- 备用 DNS：在你更改或关闭备用 DNS 时正在等待应答的域名，会改问新的备用 DNS；「备用 DNS 也没有响应」不再在一切恢复后仍在 **服务器** 标签页上停留长达 15 分钟；按名称填写的备用 DNS（`tls://…`）在 **直连 — 地址** 上也能工作，即使那里的 DNS 服务器不加密且无响应。

- 自己校验 DNSSEC 的设备（例如设置了 `DNSSEC=yes` 的 Linux）在其他设备先查询过同一网站时，不再从 DNS 缓存中得到不带签名的应答。

- 客户端速度只在 **客户端** 标签页提供（切换过去几秒后出现）：其他标签页向服务器请求的数据更少。

- 获取 HTTPS 证书的程序 lego 更新到 5.7.0（#55）。

- **服务器 → DNS** 更简洁：加密紧跟在 **服务器上的 DNS** 下面，其后是备用 DNS。

- 面板中的提示更简短、更清楚。

- **不再弹出浏览器窗口**：面板在顶部自己的提示条或窗口底部询问。字段的修改需要客户端新配置时，面板会在字段下方用橙色提示。**系统 → 域名和证书** 改为 **证书设置**，**立即获取证书** 按钮移到该窗口中。

- 界面小修复：手机上的提示不再遮住窗口的 **保存** 和 **取消**（它显示在顶部，点击即可关闭），规则窗口适配手机屏幕，波斯语中 `vpn://` 之类的链接方向正确，关闭窗口后已输入但未保存的字段会保留，错误提示更准确，提醒文字和深色主题按钮的对比度更高。

## تغییرها

- **مهم، اگر DNS روی سرور روشن است و سرور در روسیه، چین یا ایران است.** پنل دیگر خودش به DNS کشور نمی‌رود: پس از به‌روزرسانی **سرور ← DNS ← DNS پشتیبان برای «مستقیم»** خاموش است. اگر برخی کلاینت‌ها **مستقیم** می‌روند، روشنش کنید و DNS کشور را بنویسید، مثلاً <bdi>`178.22.122.100`</bdi>. وقتی سرورهای DNS از سرور شما پاسخ نمی‌دهند (DNS رمزگذاری‌شده آن‌جا اغلب قطع می‌شود)، نام سایت‌هایی که **مستقیم** می‌روند از آن پرسیده می‌شود — از همان آدرس خروجی. **اعمال برای روسیه / چین / ایران** آن را می‌نویسد و روشن می‌کند.

- **امن‌تر**: کانتینر خود پنل برای سرور AmneziaWG دیگر با همهٔ اختیارات میزبان اجرا نمی‌شود؛ نشانی خدماتی Alibaba Cloud <bdi>`100.100.100.200`</bdi> (مثل <bdi>`169.254.169.254`</bdi>) برای کلاینت‌ها بسته است؛ پس از راه‌اندازی دوبارهٔ سرور، IPv6 کلاینت‌ها تا اجرای پنل بسته است؛ حدس زدن رمز از یک شبکهٔ میزبانی هم محدود شده است؛ نصب‌کننده Docker Compose و buildx را با چکسام‌های ثابت بررسی می‌کند.

- **چند آدرس خروجی.** اگر سرور شما بیش از یک IPv4 دارد، بقیه را در **سرور ← آدرس‌های خروجی اضافه** بیفزایید — از پنل میزبانی کپی کنید (در AWS، آدرس دوم داخلی). پنل خودش آن‌ها را به سیستم سرور می‌افزاید و بررسی می‌کند سایت‌ها از هر کدام چه می‌بینند. آن‌گاه در هر انتخاب خروجی، هر آدرس «مستقیم» خودش را دارد (**مستقیم — 198.51.100.7**)، آدرس اصلی اول: یک قانون، یک کلاینت یا «پیش‌فرض» می‌تواند از آدرس خودش به اینترنت برود. خروجیِ از راه سرور دیگر هم می‌تواند از یکی از آن‌ها وصل شود (**اتصال از آدرس** در پنجره‌اش)، و سرور دیگر همان آدرس را می‌بیند. **آدرس خروجی سرور** آدرس اصلی را انتخاب می‌کند.

- **آدرس خروجی‌ای که از کار بیفتد هرگز ترافیک را از آدرس دیگری بیرون نمی‌دهد.** هر چه از آن می‌رفت مسدود می‌شود، کارتش قرمز می‌شود، در انتخاب خروجی «کار نمی‌کند» علامت می‌خورد، خروجی‌ای که از آن وصل می‌شود به پشتیبانش می‌رود و تلگرام خبر می‌دهد کی از کار افتاد و کی دوباره کار کرد.

- **مسیریابی ← آدرس‌های سرور.** بخش تازه آدرس‌های ورودی سرور (هر کدام در پیکربندی چند کلاینت است) و آدرس‌های خروجی (سایت‌ها از هر کدام چه می‌بینند و کجا به کار رفته) را نشان می‌دهد. روی آدرس بزنید تا کلاینت‌ها، قانون‌ها و خروجی‌هایی را که باید از آن استفاده کنند علامت بزنید؛ بدون علامت — دوباره آدرس اصلی. **بررسی مسیر** هم آدرس را نشان می‌دهد.

- **تغییر آدرس خروجی اصلی یعنی جابه‌جایی** همهٔ چیزهایی که فقط روی **مستقیم** هستند به آدرس تازه. پیش از ذخیره، پنل نشان می‌دهد چه جابه‌جا می‌شود، آدرس‌های حذف‌شده کجا به کار رفته‌اند (آن‌جا آدرس اصلی می‌آید) و کدام کلاینت‌ها پیکربندی تازه لازم دارند.

- **اتصال‌های باز دنبال تغییرهای شما می‌روند.** وقتی خروجی را دستی عوض می‌کنید (مسیریابی، کلاینت، خروجی، آدرس)، فقط اتصال‌هایی بسته می‌شوند که مسیرشان عوض شده و برنامه‌ها از مسیر تازه دوباره وصل می‌شوند. توزیع بار و پشتیبان‌ها همچنان چیزی را قطع نمی‌کنند.

- **آدرس پنل و آدرس کلاینت‌ها اکنون جدا هستند.** **آدرس ورودی سرور** (در پیکربندی کلاینت‌ها) و **آدرس‌های ورودی اضافه** جای **آدرس عمومی سرور** و **آدرس در پیکربندی‌ها** را گرفته‌اند؛ هر چه داشتید همان‌طور مانده است. آدرسی که پنل با آن باز می‌شود اکنون **سیستم ← آدرس پنل** است و تغییرش به کلاینت‌ها دست نمی‌زند.

- **اتصال‌های خود سرور** — به‌روزرسانی پنل، فهرست‌ها، گواهی — می‌توانند از آدرس انتخاب‌شده بیرون بروند: **سیستم ← خود سرور از کدام آدرس بیرون می‌رود**. اگر آن آدرس از کار بیفتد، سرور به آدرس سیستم برمی‌گردد تا بی‌به‌روزرسانی نماند.

- **DNS ویژهٔ قانون و DNS پشتیبان می‌توانند رمزگذاری‌شده باشند**: برای DoH <bdi>`https://…/dns-query`</bdi>، برای DoH فقط با HTTP/3 <bdi>`h3://…/dns-query`</bdi> و برای DoT <bdi>`tls://…`</bdi>، مثلاً <bdi>`tls://common.dot.dns.yandex.net`</bdi>. هر کدام دقیقاً همان‌طور که نوشته شده پرسیده می‌شود. HTTP/3 روی UDP می‌رود و ارائه‌دهنده ممکن است آن را جدا از HTTPS ببندد — نشانی دوم را <bdi>`https://`</bdi> بنویسید.

- **DNS روی سرور اکنون به همهٔ درخواست‌های DNS کلاینت‌ها پاسخ می‌دهد** — هم به DNS دوم پیکربندی‌شان و هم به DNSی که در دستگاه یا برنامه نوشته شده: نام‌ها دیگر از کنار خروجی یا بدون رمزگذاری نمی‌روند و پیکربندی‌هایی که پیش‌تر داده شده‌اند لازم نیست دوباره وارد شوند. تا پنل دوباره راه‌اندازی یا به‌روز می‌شود، نام‌ها چند ثانیه پیدا نمی‌شوند.

- **سرورهای ARM** ‏(Oracle Free، Hetzner ARM): ایمیج سرور AmneziaWG اکنون برای arm64 هم ساخته می‌شود — پیش‌تر VPN در کانتینر خودش آن‌جا اصلاً اجرا نمی‌شد. اگر ایمیج آماده به پردازندهٔ سرور نخورد، نصب‌کننده آن را روی سرور می‌سازد.

- **DoH اکنون با HTTP/2 کار می‌کند**: Quad9 و Yandex دیگر به DoH با HTTP/1.1 پاسخ نمی‌دهند و با آن‌ها DoH اصلاً کار نمی‌کرد — از جمله Quad9 در سرورهای DNS با رمزگذاری پیش‌فرض DoH.

- DNS رمزگذاری‌شده روی سرور برای هر درخواست 40 تا 150 میلی‌ثانیه سریع‌تر پاسخ می‌دهد.

- **یک سایت کُند دیگر همه را به DNS پشتیبان نمی‌برد.** یک نام که سرورهای DNS به‌موقع به آن پاسخ ندادند (سرورهای نامِ خودِ آن سایت پاسخ نمی‌دهند) یا یک بستهٔ گم‌شده «سرورهای DNS پاسخ نمی‌دهند» حساب می‌شد: 2 دقیقه همهٔ کلاینت‌های **مستقیم** بدون رمزگذاری از DNS کشور می‌پرسیدند. اکنون پنل اول سرورهای DNS را بررسی می‌کند (وقتی پاسخ می‌دهند، کسری از ثانیه)؛ جایی که DNS رمزگذاری‌شده واقعاً قطع است، DNS پشتیبان مثل قبل بی‌درنگ جایگزین می‌شود.

- **DNS روی سرور زیر بار.** روی سرور پرکار، هجوم ناگهانی نام‌ها هنوز می‌توانست همهٔ کلاینت‌های **مستقیم** را ۲ دقیقه به DNS پشتیبان ببرد و برخی نام‌ها بی‌پاسخ می‌ماندند؛ و وقتی یک دستگاه بارها نامی را می‌پرسید که پاسخ نمی‌دهد، هر سایت تازه برای همهٔ کاربران **مستقیم** چند ثانیه دیرتر باز می‌شد. هر دو درست شدند.

- **بررسی مسیر** دوباره نشانی دامنه را از راه خروجی کلاینت می‌گیرد، همان‌طور که باید: از 1.21.0 از DNS خود سرور می‌پرسید که در روسیه، چین یا ایران ممکن است نشانی جعلی بدهد.

- **راه‌های کمتر برای دور زدن خروجی و گیر کردن**: با تیک **قانون‌های دامنه فقط برای نشانی‌هایی که این DNS برگردانده**، نخستین اتصال به نشانی تازهٔ سایتی از قانون دیگر از کنار خروجی نمی‌رود؛ WireGuard معمولی روی همان سرور که همهٔ ترافیک را از خودش می‌برد (wg-quick، مثلاً WARP) دیگر UDP کلاینت‌ها را از کنار خروجی و **مسدود** رد نمی‌کند؛ قطع شدن SSH هنگام <bdi>`awg-router update`</bdi> دیگر VPN را خاموش نمی‌گذارد؛ گیر کردن amneziawg-go یک خروجی دیگر جلوی اعمال قانون‌ها را نمی‌گیرد — کلاینت‌هایش به پشتیبان می‌روند؛ پشتیبان‌های بزرگ‌تر از 4 مگابایت بازگردانی می‌شوند؛ قانون‌های دامنه وقتی پنل درست پس از اجرا تنظیماتشان را عوض می‌کند از کار نمی‌افتند.

- بازگردانی پشتیبان روی سرور دیگر: آدرس‌ها مال هر سرور هستند و منتقل نمی‌شوند؛ هر جا پشتیبان از آدرسی استفاده می‌کرد که این سرور ندارد، آدرس اصلی می‌آید و پنل می‌گوید کجا.

- ربات تلگرام «مستقیم — آدرس» را نشان می‌دهد وقتی کلاینت از آدرسی غیر از آدرس اصلی بیرون می‌رود.

- فشردن دوبارهٔ **اعمال برای …** اکنون قانون‌های کشور را مثل بار اول می‌کند — مستقیم، روشن، با DNS فعلی کشور، در انتها (محدودیت سرعت و سقف ماهانه می‌مانند).

- DNS پشتیبان: نامی که هنگام تغییر یا خاموش کردن پشتیبان در انتظار پاسخ بود، به پشتیبان تازه می‌رود؛ «DNS پشتیبان هم پاسخ نمی‌دهد» دیگر تا ۱۵ دقیقه پس از درست شدن همه چیز در زبانهٔ **سرور** نمی‌ماند؛ پشتیبانی که با نام نوشته شده (<bdi>`tls://…`</bdi>) روی **مستقیم — آدرس** هم کار می‌کند، وقتی سرورهای DNS آن‌جا بدون رمزگذاری‌اند و پاسخ نمی‌دهند.

- دستگاهی که خودش DNSSEC را بررسی می‌کند (مثلاً Linux با <bdi>`DNSSEC=yes`</bdi>) دیگر از حافظهٔ پنهان DNS پاسخ بی‌امضا نمی‌گیرد، وقتی دستگاه دیگری همان سایت را زودتر پرسیده باشد.

- سرعت کلاینت‌ها فقط در زبانهٔ **کلاینت‌ها** می‌آید (چند ثانیه پس از رفتن به آن): زبانه‌های دیگر کمتر از سرور می‌پرسند.

- lego، برنامه‌ای که گواهی HTTPS را می‌گیرد، به 5.7.0 به‌روز شد ‏(#55).

- **سرور ← DNS** ساده‌تر شد: رمزگذاری درست زیر **DNS روی سرور** است و پس از آن DNS پشتیبان.

- راهنماهای پنل کوتاه‌تر و روشن‌تر شده‌اند.

- **دیگر پنجرهٔ مرورگر باز نمی‌شود**: پنل با نوار خودش در بالا یا در پایین پنجره می‌پرسد. زیر فیلدی که تغییرش پیکربندی تازهٔ کلاینت‌ها را لازم دارد، پنل این را نارنجی می‌نویسد. **سیستم ← دامنه و گواهی** اکنون **تنظیمات گواهی** است و دکمهٔ **دریافت گواهی اکنون** در همین پنجره است.

- اصلاح‌های کوچک رابط: پیام دیگر **ذخیره** و **انصراف** پنجره را در گوشی نمی‌پوشاند (بالا می‌آید و با زدن بسته می‌شود)، پنجرهٔ قانون در صفحهٔ گوشی جا می‌شود، پیوندهایی مثل <bdi>`vpn://`</bdi> در فارسی درست خوانده می‌شوند، آنچه در فیلدها نوشته و ذخیره نشده پس از بستن پنجره می‌ماند، پیام‌های خطا دقیق‌ترند، و تضاد رنگ هشدارها و دکمه‌های پوستهٔ تیره بیشتر شده است.

## به‌روزرسانی

در پنل **سیستم ← به‌روزرسانی** (از 1.4.0)، یا روی سرور:

    awg-router update

نصب تازه (Ubuntu یا Debian، با root):

    curl -fsSL https://raw.githubusercontent.com/r-slashslash/AWG-Router/main/install.sh | bash

**بازگشت به 1.24.0**: <bdi>`AWGR_SRC_URL=https://github.com/r-slashslash/AWG-Router/releases/download/v1.24.0/awg-router.tar.gz awg-router update`</bdi>؛ تنظیمات و پشتیبان‌ها همان می‌مانند. نسخهٔ 1.24.0 آدرس‌های خروجی را نمی‌شناسد: **مستقیم — آدرس** آن‌جا از آدرس سیستم سرور می‌رود (مسدود نمی‌شود)، خروجی‌ها هم از همان وصل می‌شوند، و آدرس‌هایی که پنل افزوده تا راه‌اندازی دوبارهٔ سرور در سیستم آن می‌مانند. آدرس‌های ورودی و آدرس پنل همچنان کار می‌کنند (IPی که پنل به سیستم افزوده — تا راه‌اندازی دوباره). در حالت کانتینر، شبکه‌های Docker <bdi>`zz-awgr-out-N`</bdi> به کانتینر AWG وصل می‌مانند؛ در 1.24.0 ترافیکی از آن‌ها نمی‌رود (حذف: <bdi>`docker network disconnect zz-awgr-out-1 amnezia-awg2 && docker network rm zz-awgr-out-1`</bdi>؛ نام کانتینر ممکن است <bdi>`amnezia-awg`</bdi> باشد). DNS روی سرور آن‌جا دیگر درخواست‌های سرورهای DNS دیگر را نمی‌گیرد. DNS ویژهٔ قانون که به‌صورت DoH یا DoT نوشته شده آن‌جا از سرورهای DNS معمول پرسیده می‌شود (آدرس‌های معمولی کنارش کار می‌کنند)، و تنظیم DNS پشتیبان به کار نمی‌رود — 1.24.0 مثل قبل DNS کشور را خودش انتخاب می‌کند. اگر در 1.24.0 چیزی را در **مسیریابی** ذخیره کنید، قانون‌ها **مستقیم — آدرس** و ورودی‌های DoH/DoT در DNS ویژه‌شان را از دست می‌دهند: پس از بازگشت به 1.25.0 فقط **مستقیم** ساده و آدرس‌های معمولی DNS می‌ماند.
