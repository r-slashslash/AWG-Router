## What's changed

- **Several outgoing addresses.** If your server has more than one IPv4 address, add the others in **Server → Additional outgoing addresses** — copy them from your hosting panel (on AWS, the internal second address). The panel adds them to the server's system itself and checks what websites see from each. Then every exit choice has **Direct** per address (**Direct — 198.51.100.7**), main one first: a rule, a client or Default can go out to the internet from its own address. An exit through another server can connect from one of them too (**Connect from address** in its window), and the other server sees that address. **Server outgoing address** picks the main one.

- **Routing → Server addresses.** A new block shows the server's incoming addresses (how many clients have each in their config) and outgoing ones (what websites see from each and where it is used). Tap an address to tick clients, rules and exits that should use it; untick — back to the main address. **Route check** shows the address too.

- **An outgoing address that stops working never lets traffic out from another one.** What goes through it is blocked, its card turns red, exit choices mark it "not working", an exit connecting from it switches to its fallback, and Telegram tells you when it stops and when it works again.

- **Changing the main outgoing address moves** everything on plain **Direct** to the new one. Before saving, the panel shows what moves, where removed addresses are used (they go to the main one) and which clients need a new config.

- **Open connections follow your changes.** When you change an exit by hand (routing, a client, an exit, an address), only the connections whose path changed are closed, and apps reconnect over the new path. Load balancing and fallbacks still don't drop anything.

- **The panel address and the clients' address are now separate.** **Server incoming address** (in client configs) and **Additional incoming addresses** replace **Server public address** and **Address in configs**; everything you had stays as it was. The address the panel opens at is now **System → Panel address**, and changing it doesn't touch clients.

- **The server's own connections** — panel updates, lists, the certificate — can go out from a chosen address: **System → Address the server itself goes out from**. If that address stops working, the server goes back to the system address, so it isn't left without updates.

- **Fallback DNS for Direct is now a setting.** **Server → DNS → Fallback DNS for "Direct"**: when the DNS servers don't answer from your server (encrypted DNS is often cut in Russia, China and Iran), names of sites that go **Direct** are asked there instead — from the same outgoing address. **Apply for Russia / China / Iran** fills in that country's DNS and turns it on. Before, the panel did this by itself on servers in these countries; after the update it is off — **if your server is in Russia, China or Iran and some clients go Direct, turn it on** and enter the country's DNS, for example `77.88.8.8`.

- **A rule's own DNS and the fallback DNS can be encrypted**: `https://…/dns-query` for DoH, `tls://…` for DoT, for example `tls://common.dot.dns.yandex.net`. Each is asked exactly the way it is written.

- Restoring a backup on another server: addresses belong to each server and aren't copied; where the backup used an address this server doesn't have, the main one is used, and the panel says where.

- The Telegram bot shows "direct — address" where a client goes out from a non-main address.

- **Apply for Iran** now uses Shecan's current address `94.232.174.194` (the one on its site). A `.ir` rule made earlier keeps the old addresses — replace them if `.ir` sites are slow to open.

- **Server → DNS** is tidier: encryption comes right under **DNS on the server**, then the fallback DNS.

- **Route check** resolves a domain through the client's exit again, as it should: since 1.21.0 it asked the server's own DNS, which in Russia, China or Iran may give a spoofed address.

- lego, the program that gets the HTTPS certificate, is updated to 5.7.0 (#55).

New install (Ubuntu or Debian, as root):

## Что изменилось

- **Несколько исходящих адресов.** Если у сервера больше одного IPv4, добавьте остальные в **«Сервер» → «Дополнительные исходящие адреса»** — скопируйте их из панели хостинга (в AWS — внутренний второй адрес). Панель сама добавит их в систему сервера и проверит, что с каждого видят сайты. Тогда в каждом выборе выхода у каждого адреса своё **«Напрямую»** (**«Напрямую — 198.51.100.7»**), основной первым: правило, клиент или «По умолчанию» могут выходить в интернет со своего адреса. Выход через другой сервер тоже может подключаться с одного из них (**«Подключаться с адреса»** в его окне) — второй сервер увидит этот адрес. **«Исходящий адрес сервера»** выбирает основной.

- **«Маршрутизация» → «Адреса сервера».** Новый блок показывает входящие адреса сервера (у скольких клиентов каждый в конфиге) и исходящие (что с каждого видят сайты и где он стоит). Нажмите на адрес, чтобы отметить клиентов, правила и выходы, которым он нужен; снятая галочка — снова основной адрес. **«Проверка маршрута»** тоже показывает адрес.

- **Исходящий адрес, который перестал работать, никогда не выпускает трафик с другого.** Всё, что шло через него, блокируется, его карточка становится красной, в выборе выхода он помечен «не работает», выход, который с него подключается, переходит на свой резерв, а Telegram сообщает, когда адрес перестал и когда снова начал работать.

- **Смена основного исходящего адреса — это переезд** всего, что стоит просто на **«Напрямую»**, на новый адрес. Перед сохранением панель покажет, что переедет, где стоят убранные адреса (там будет основной) и каким клиентам нужен новый конфиг.

- **Открытые соединения идут за вашими изменениями.** Когда вы вручную меняете выход (маршрутизация, клиент, выход, адрес), закрываются только соединения, у которых сменился путь, и приложения переподключаются по новому. Балансировка и резервы по-прежнему ничего не рвут.

- **Адрес панели и адрес для клиентов теперь раздельно.** **«Входящий адрес сервера»** (в конфигах клиентов) и **«Дополнительные входящие адреса»** заменили **«Внешний адрес сервера»** и **«Адрес в конфигах»**; всё, что было, осталось как было. Адрес, по которому открывается панель, теперь — **«Система» → «Адрес панели»**, и его смена клиентов не трогает.

- **Собственные соединения сервера** — обновления панели, списки, сертификат — могут выходить с выбранного адреса: **«Система» → «С какого адреса выходит сам сервер»**. Если этот адрес перестал работать, сервер вернётся к адресу системы, чтобы не остаться без обновлений.

- **Запасной DNS для «Напрямую» — теперь настройка.** **«Сервер» → «DNS» → «Запасной DNS для «Напрямую»»**: когда серверы DNS не отвечают с вашего сервера (шифрованный DNS часто режут в России, Китае и Иране), имена сайтов, которые идут **«Напрямую»**, спрашиваются у него — с того же исходящего адреса. **«Применить для России / Китая / Ирана»** вписывает DNS этой страны и включает его. Раньше панель делала это сама на серверах в этих странах; после обновления он выключен — **если сервер в России, Китае или Иране и часть клиентов идёт «Напрямую», включите его** и впишите DNS страны, например `77.88.8.8`.

- **Свой DNS правила и запасной DNS могут быть шифрованными**: `https://…/dns-query` — DoH, `tls://…` — DoT, например `tls://common.dot.dns.yandex.net`. Каждый спрашивается ровно так, как вписан.

- Восстановление резервной копии на другом сервере: адреса у каждого сервера свои и не переносятся; где копия использовала адрес, которого у этого сервера нет, будет основной, и панель скажет где.

- Бот в Telegram показывает «напрямую — адрес», когда клиент выходит не с основного адреса.

- **«Применить для Ирана»** теперь вписывает нынешний адрес Shecan — `94.232.174.194` (так на его сайте). В правиле `.ir`, сделанном раньше, остались прежние адреса — замените их, если сайты `.ir` долго открываются.

- **«Сервер» → «DNS»** стал проще: шифрование — сразу под **«DNS на сервере»**, за ним запасной DNS.

- **«Проверка маршрута»** снова узнаёт адрес домена через выход клиента, как и задумано: с 1.21.0 она спрашивала DNS самого сервера, а он в России, Китае или Иране может подменить адрес.

- lego — программа, которая получает сертификат HTTPS, — обновлена до 5.7.0 (#55).

## 改动

- **多个出站地址。** 如果你的服务器有不止一个 IPv4 地址，请在 **服务器 → 附加出站地址** 中添加其他地址——从主机商面板复制（在 AWS 上填写内部的第二个地址）。面板会自动把它们添加到服务器系统中，并检查网站从每个地址看到的是什么。之后每个出口选择中，每个地址都有自己的 **直连**（**直连 — 198.51.100.7**），主地址排在最前：规则、客户端或默认出口都可以从自己的地址访问互联网。经其他服务器的出口也可以从其中一个地址连接（出口窗口中的 **从此地址连接**），另一台服务器看到的就是这个地址。**服务器出站地址** 用于选择主地址。

- **路由 → 服务器地址。** 新区块显示服务器的入站地址（每个地址写在多少个客户端的配置中）和出站地址（网站从每个地址看到什么，以及它用在哪里）。点击地址即可勾选应使用它的客户端、规则和出口；取消勾选——回到主地址。**路由检测** 也会显示地址。

- **出站地址不可用时，绝不会让流量从其他地址出去。** 经过它的流量会被阻止，它的卡片变红，出口列表中标为「不可用」，从它连接的出口切换到自己的备用出口，并通过 Telegram 通知地址何时不可用、何时恢复。

- **更换主出站地址就是迁移**：所有只选了 **直连** 的地方都会迁移到新地址。保存前，面板会显示哪些会迁移、被删除的地址用在哪里（那里将改用主地址），以及哪些客户端需要新配置。

- **已打开的连接会跟随你的改动。** 手动更改出口时（路由、客户端、出口、地址），只关闭路径发生变化的连接，应用会按新路径重新连接。负载均衡和备用出口仍然不会断开任何连接。

- **面板地址和客户端地址现在分开了。** **服务器入站地址**（写在客户端配置中）和 **附加入站地址** 取代了 **服务器公网地址** 和 **配置中的地址**；原有设置保持不变。打开面板的地址现在在 **系统 → 面板地址**，修改它不会影响客户端。

- **服务器自身的连接**——面板更新、列表、证书——可以从选定的地址访问外网：**系统 → 服务器自身从哪个地址访问外网**。如果该地址不可用，服务器会回到系统地址，以免收不到更新。

- **「直连」的备用 DNS 现在是一项设置。** **服务器 → DNS → 「直连」的备用 DNS**：当 DNS 服务器从你的服务器无法响应时（在俄罗斯、中国和伊朗，加密 DNS 常被阻断），**直连** 网站的名称改向它查询——从同一出站地址发出。**应用于俄罗斯 / 中国 / 伊朗** 会填入该国家的 DNS 并开启它。以前面板在这些国家的服务器上会自动这样做；更新后它是关闭的——**如果服务器在俄罗斯、中国或伊朗且有客户端直连，请开启它**并填入该国的 DNS，例如 `223.5.5.5`。

- **规则的专用 DNS 和备用 DNS 可以加密**：DoH 写 `https://…/dns-query`，DoT 写 `tls://…`，例如 `https://dns.alidns.com/dns-query`。每个都严格按所写的方式查询。

- 在另一台服务器上恢复备份：地址属于各自的服务器，不会被复制；备份中使用了本服务器没有的地址的地方会改用主地址，面板会说明是哪些地方。

- 当客户端不是从主地址访问外网时，Telegram 机器人显示「直连 — 地址」。

- **应用于伊朗** 现在使用 Shecan 当前的地址 `94.232.174.194`（其网站所列）。之前创建的 `.ir` 规则仍保留旧地址——如果 `.ir` 网站打开很慢，请替换。

- **服务器 → DNS** 更简洁：加密紧跟在 **服务器上的 DNS** 下面，其后是备用 DNS。

- **路由检测** 重新经由客户端的出口解析域名，本应如此：自 1.21.0 起它询问的是服务器自身的 DNS，而在俄罗斯、中国或伊朗，它可能返回被篡改的地址。

- 获取 HTTPS 证书的程序 lego 更新到 5.7.0（#55）。

## تغییرها

- **چند آدرس خروجی.** اگر سرور شما بیش از یک IPv4 دارد، بقیه را در **سرور ← آدرس‌های خروجی اضافه** بیفزایید — از پنل میزبانی کپی کنید (در AWS، آدرس دوم داخلی). پنل خودش آن‌ها را به سیستم سرور می‌افزاید و بررسی می‌کند سایت‌ها از هر کدام چه می‌بینند. آن‌گاه در هر انتخاب خروجی، هر آدرس «مستقیم» خودش را دارد (**مستقیم — 198.51.100.7**)، آدرس اصلی اول: یک قانون، یک کلاینت یا «پیش‌فرض» می‌تواند از آدرس خودش به اینترنت برود. خروجیِ از راه سرور دیگر هم می‌تواند از یکی از آن‌ها وصل شود (**اتصال از آدرس** در پنجره‌اش)، و سرور دیگر همان آدرس را می‌بیند. **آدرس خروجی سرور** آدرس اصلی را انتخاب می‌کند.

- **مسیریابی ← آدرس‌های سرور.** بخش تازه آدرس‌های ورودی سرور (هر کدام در پیکربندی چند کلاینت است) و آدرس‌های خروجی (سایت‌ها از هر کدام چه می‌بینند و کجا به کار رفته) را نشان می‌دهد. روی آدرس بزنید تا کلاینت‌ها، قانون‌ها و خروجی‌هایی را که باید از آن استفاده کنند علامت بزنید؛ بدون علامت — دوباره آدرس اصلی. **بررسی مسیر** هم آدرس را نشان می‌دهد.

- **آدرس خروجی‌ای که از کار بیفتد هرگز ترافیک را از آدرس دیگری بیرون نمی‌دهد.** هر چه از آن می‌رفت مسدود می‌شود، کارتش قرمز می‌شود، در انتخاب خروجی «کار نمی‌کند» علامت می‌خورد، خروجی‌ای که از آن وصل می‌شود به پشتیبانش می‌رود و تلگرام خبر می‌دهد کی از کار افتاد و کی دوباره کار کرد.

- **تغییر آدرس خروجی اصلی یعنی جابه‌جایی** همهٔ چیزهایی که فقط روی **مستقیم** هستند به آدرس تازه. پیش از ذخیره، پنل نشان می‌دهد چه جابه‌جا می‌شود، آدرس‌های حذف‌شده کجا به کار رفته‌اند (آن‌جا آدرس اصلی می‌آید) و کدام کلاینت‌ها پیکربندی تازه لازم دارند.

- **اتصال‌های باز دنبال تغییرهای شما می‌روند.** وقتی خروجی را دستی عوض می‌کنید (مسیریابی، کلاینت، خروجی، آدرس)، فقط اتصال‌هایی بسته می‌شوند که مسیرشان عوض شده و برنامه‌ها از مسیر تازه دوباره وصل می‌شوند. توزیع بار و پشتیبان‌ها همچنان چیزی را قطع نمی‌کنند.

- **آدرس پنل و آدرس کلاینت‌ها اکنون جدا هستند.** **آدرس ورودی سرور** (در پیکربندی کلاینت‌ها) و **آدرس‌های ورودی اضافه** جای **آدرس عمومی سرور** و **آدرس در پیکربندی‌ها** را گرفته‌اند؛ هر چه داشتید همان‌طور مانده است. آدرسی که پنل با آن باز می‌شود اکنون **سیستم ← آدرس پنل** است و تغییرش به کلاینت‌ها دست نمی‌زند.

- **اتصال‌های خود سرور** — به‌روزرسانی پنل، فهرست‌ها، گواهی — می‌توانند از آدرس انتخاب‌شده بیرون بروند: **سیستم ← خود سرور از کدام آدرس بیرون می‌رود**. اگر آن آدرس از کار بیفتد، سرور به آدرس سیستم برمی‌گردد تا بی‌به‌روزرسانی نماند.

- **DNS پشتیبان برای «مستقیم» اکنون یک تنظیم است.** **سرور ← DNS ← DNS پشتیبان برای «مستقیم»**: وقتی سرورهای DNS از سرور شما پاسخ نمی‌دهند (DNS رمزگذاری‌شده در روسیه، چین و ایران اغلب قطع می‌شود)، نام سایت‌هایی که **مستقیم** می‌روند از آن پرسیده می‌شود — از همان آدرس خروجی. **اعمال برای روسیه / چین / ایران** DNS همان کشور را می‌نویسد و روشنش می‌کند. پیش‌تر پنل این کار را روی سرورهای این کشورها خودش انجام می‌داد؛ پس از به‌روزرسانی خاموش است — **اگر سرور در روسیه، چین یا ایران است و برخی کلاینت‌ها مستقیم می‌روند، روشنش کنید** و DNS کشور را بنویسید، مثلاً <bdi>`94.232.174.194`</bdi>.

- **DNS ویژهٔ قانون و DNS پشتیبان می‌توانند رمزگذاری‌شده باشند**: برای DoH <bdi>`https://…/dns-query`</bdi> و برای DoT <bdi>`tls://…`</bdi>. هر کدام دقیقاً همان‌طور که نوشته شده پرسیده می‌شود.

- بازگردانی پشتیبان روی سرور دیگر: آدرس‌ها مال هر سرور هستند و منتقل نمی‌شوند؛ هر جا پشتیبان از آدرسی استفاده می‌کرد که این سرور ندارد، آدرس اصلی می‌آید و پنل می‌گوید کجا.

- ربات تلگرام «مستقیم — آدرس» را نشان می‌دهد وقتی کلاینت از آدرسی غیر از آدرس اصلی بیرون می‌رود.

- **اعمال برای ایران** اکنون آدرس فعلی Shecan را به کار می‌برد: <bdi>`94.232.174.194`</bdi> (همان که در سایتش آمده). قانون <bdi>`.ir`</bdi> که پیش‌تر ساخته شده آدرس‌های قبلی را نگه می‌دارد — اگر سایت‌های <bdi>`.ir`</bdi> دیر باز می‌شوند، عوضشان کنید.

- **سرور ← DNS** ساده‌تر شد: رمزگذاری درست زیر **DNS روی سرور** است و پس از آن DNS پشتیبان.

- **بررسی مسیر** دوباره نشانی دامنه را از راه خروجی کلاینت می‌گیرد، همان‌طور که باید: از 1.21.0 از DNS خود سرور می‌پرسید که در روسیه، چین یا ایران ممکن است نشانی جعلی بدهد.

- lego، برنامه‌ای که گواهی HTTPS را می‌گیرد، به 5.7.0 به‌روز شد ‏(#55).

## به‌روزرسانی

در پنل **سیستم ← به‌روزرسانی** (از 1.4.0)، یا روی سرور:

    awg-router update

نصب تازه (Ubuntu یا Debian، با root):

    curl -fsSL https://raw.githubusercontent.com/r-slashslash/AWG-Router/main/install.sh | bash

**بازگشت به 1.24.0**: <bdi>`AWGR_SRC_URL=https://github.com/r-slashslash/AWG-Router/releases/download/v1.24.0/awg-router.tar.gz awg-router update`</bdi>؛ تنظیمات و پشتیبان‌ها همان می‌مانند. نسخهٔ 1.24.0 آدرس‌های خروجی را نمی‌شناسد: **مستقیم — آدرس** آن‌جا از آدرس سیستم سرور می‌رود (مسدود نمی‌شود)، خروجی‌ها هم از همان وصل می‌شوند، و آدرس‌هایی که پنل افزوده تا راه‌اندازی دوبارهٔ سرور در سیستم آن می‌مانند. آدرس‌های ورودی و آدرس پنل همچنان کار می‌کنند. DNS ویژهٔ قانون که به‌صورت DoH یا DoT نوشته شده آن‌جا از سرورهای DNS معمول پرسیده می‌شود (آدرس‌های معمولی کنارش کار می‌کنند)، و تنظیم DNS پشتیبان به کار نمی‌رود — 1.24.0 مثل قبل DNS کشور را خودش انتخاب می‌کند.
