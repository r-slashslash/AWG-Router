## What's changed

- **DNS on the server.** A new optional setting: **Server → Client settings → DNS on the server**. Clients ask the server for DNS, and the server forwards the query to the servers from the "DNS" field through the client's own exit, the same way the client's traffic goes, and caches the answers. It is similar to AmneziaDNS, but without its catch in a cascade: a resolver on the entry server asks from the entry country, so the local ISP can spoof answers and CDNs send clients to nodes near the entry server while their traffic goes out abroad. After turning it on, give clients new configs. How to use it best is in the hint under the setting and in the README section "DNS on the server".
- **Exit with a domain name in Endpoint.** If an exit's config had `Endpoint = name:port` instead of an IP address, the tunnel never came up: `awg setconf` waited 30 seconds and failed. The cause was DNS: the command runs in the Amnezia container's network, but with the panel's resolver settings, and on hosts with systemd-resolved they point to 127.0.0.53, where nobody listens there. The panel now resolves the name itself before the tunnel is created. If the name can't be resolved, the exit shows a clear error. Thanks to @LCF30 for the detailed report.
- **New address of the exit picked up by itself.** If such an exit stops answering, the panel resolves the name again and switches the tunnel to the new address without a restart. Change the DNS record, and the exit follows. A working tunnel is never touched.
- **Exit check and the server's IPv4.** For the same reason the check could show "external IP unknown", and the bot showed a dash instead of the server's IPv4: the panel stopped looking for it after 10 minutes. The panel now gives the check the addresses itself and keeps looking for the IPv4 until it finds it.
- **Bot: Server › Status.** IPv4 shows "detecting…" or "unknown" instead of a dash, IPv6 says "none on the server" when there is none, and a new line shows DNS on the server: off, running (with query counters) or not working.

## Что изменилось

- **DNS на сервере.** Новая настройка, по желанию: **«Сервер» → «Настройки клиентов» → «DNS на сервере»**. Клиенты спрашивают DNS у сервера, а он пересылает запрос серверам из поля «DNS» через выход самого клиента — тем же путём, что и его трафик, — и кэширует ответы. Похоже на AmneziaDNS, но без его подвоха в каскаде: резолвер на входном сервере спрашивает из страны входа, поэтому провайдер может подменить ответы, а CDN отправляет клиентов на узлы рядом с входным сервером, хотя их трафик уходит за границу. После включения отдайте клиентам новые конфиги. Как лучше пользоваться — в подсказке под настройкой и в разделе README «DNS на сервере».
- **Выход с доменным именем в Endpoint.** Если в конфиге выхода вместо IP-адреса стояло `Endpoint = имя:порт`, туннель не поднимался: `awg setconf` ждал 30 секунд и завершался ошибкой. Причина в DNS: команда выполняется в сети контейнера Amnezia, но с настройками резолвера панели, а на серверах с systemd-resolved они указывают на 127.0.0.53, где в той сети никто не слушает. Теперь панель сама разбирает имя до создания туннеля. Если разобрать не удалось, у выхода появляется понятная ошибка. Спасибо @LCF30 за подробный отчёт.
- **Новый адрес выхода подхватывается сам.** Если такой выход перестал отвечать, панель заново разбирает имя и переводит туннель на новый адрес без перезапуска. Смените запись DNS — и выход последует за ней. Работающий туннель не трогается.
- **Проверка выхода и IPv4 сервера.** По той же причине проверка могла показывать «внешний IP не определён», а бот вместо IPv4 сервера показывал прочерк: через 10 минут панель переставала его искать. Теперь адреса для проверки панель передаёт сама и ищет IPv4, пока не найдёт.
- **Бот: «Сервер › Состояние».** Для IPv4 вместо прочерка — «определяется…» или «не определён», для IPv6 — «на сервере нет», если его нет, и новая строка о DNS на сервере: выключен, работает (со счётчиками запросов) или не работает.

## 改动

- **服务器上的 DNS。** 新的可选设置：**服务器 → 客户端设置 → 服务器上的 DNS**。客户端向服务器查询 DNS，服务器经由该客户端自己的出口（与其流量相同的路径）把查询转发给「DNS」字段中的服务器，并缓存答案。它类似于 AmneziaDNS，但没有它在级联中的陷阱：入口服务器上的解析器从入口国家发出查询，因此运营商可能篡改答案，CDN 会把客户端引向靠近入口服务器的节点，而他们的流量却在境外发出。开启后请给客户端新的配置。最佳用法见设置下方的提示和 README 中的「服务器上的 DNS」一节。
- **Endpoint 为域名的出口。** 如果出口配置中的 Endpoint 写的是 `name:port` 而不是 IP 地址，隧道就无法建立：`awg setconf` 等待 30 秒后报错。原因在于 DNS：该命令在 Amnezia 容器的网络中运行，却使用面板的解析器设置；在使用 systemd-resolved 的服务器上，它指向 127.0.0.53，而那个网络里没有任何程序监听。现在面板在创建隧道之前自己解析域名。如果无法解析，出口会显示明确的错误。感谢 @LCF30 提供详细的报告。
- **自动获取出口的新地址。** 如果这样的出口不再响应，面板会重新解析域名，并在不重启的情况下把隧道切换到新地址。修改 DNS 记录，出口就会跟着变。正常工作的隧道不会被改动。
- **出口检测与服务器的 IPv4。** 由于同样的原因，检测可能显示「无法确定外部 IP」，而机器人显示的服务器 IPv4 是一个短横线：面板在 10 分钟后就不再查找它。现在由面板把地址交给检测，并持续查找 IPv4 直到找到为止。
- **机器人：服务器 › 状态。** IPv4 不再显示短横线，而是「正在检测…」或「未知」；没有 IPv6 时显示「服务器上没有」；新增一行显示服务器上的 DNS：已关闭、运行中（带查询计数）或未运行。

## تغییرها

- **DNS روی سرور.** یک تنظیم تازه و اختیاری: **سرور ← تنظیمات کلاینت‌ها ← DNS روی سرور**. کلاینت‌ها DNS را از سرور می‌پرسند و سرور پرسش را از خروجی خود همان کلاینت — از همان مسیر ترافیکش — به سرورهای فیلد «DNS» می‌فرستد و پاسخ‌ها را نگه می‌دارد. شبیه AmneziaDNS است، اما بدون دام آن در آبشار: resolver روی سرور ورودی از کشور ورودی می‌پرسد، پس ارائه‌دهنده می‌تواند پاسخ‌ها را جعل کند و CDNها کلاینت‌ها را به گره‌های نزدیک سرور ورودی می‌فرستند، در حالی که ترافیکشان از خارج بیرون می‌رود. پس از روشن کردن، پیکربندی تازه به کلاینت‌ها بدهید. بهترین روش استفاده در راهنمای زیر تنظیم و در بخش «DNS روی سرور» در README آمده است.
- **خروجی با نام دامنه در Endpoint.** اگر در پیکربندی خروجی به‌جای نشانی IP مقدار `Endpoint = name:port` بود، تونل بالا نمی‌آمد: `awg setconf` سی ثانیه منتظر می‌ماند و با خطا تمام می‌شد. علت DNS بود: این فرمان در شبکهٔ کانتینر Amnezia اجرا می‌شود، اما با تنظیمات resolver پنل، و روی سرورهای دارای systemd-resolved آن به 127.0.0.53 اشاره می‌کند، جایی که در آن شبکه کسی گوش نمی‌دهد. اکنون پنل پیش از ساخت تونل خودش نام را تبدیل می‌کند. اگر تبدیل نشود، خروجی خطای روشنی نشان می‌دهد. از @LCF30 برای گزارش دقیقش سپاسگزاریم.
- **نشانی تازهٔ خروجی خودبه‌خود گرفته می‌شود.** اگر چنین خروجی‌ای پاسخ ندهد، پنل نام را دوباره تبدیل می‌کند و تونل را بدون راه‌اندازی مجدد به نشانی تازه می‌برد. رکورد DNS را عوض کنید تا خروجی دنبالش برود. به تونلی که کار می‌کند دست زده نمی‌شود.
- **بررسی خروجی و IPv4 سرور.** به همین دلیل بررسی ممکن بود «IP خارجی نامشخص» نشان دهد و ربات به‌جای IPv4 سرور خط تیره نشان می‌داد: پنل پس از ۱۰ دقیقه دیگر دنبال آن نمی‌گشت. اکنون پنل نشانی‌ها را خودش به بررسی می‌دهد و تا IPv4 را پیدا نکند دست برنمی‌دارد.
- **ربات: سرور › وضعیت.** برای IPv4 به‌جای خط تیره «در حال تشخیص…» یا «نامشخص»، برای IPv6 در صورت نبودن «روی سرور نیست»، و یک خط تازه برای DNS روی سرور: خاموش، در حال کار (با شمارش پرسش‌ها) یا از کار افتاده.
