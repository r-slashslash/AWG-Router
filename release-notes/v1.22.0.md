## What's changed

- **Stronger sign-in with a code.** If someone knows your panel password, wrong codes from the app are now counted from all addresses together: after 10 wrong codes, sign-in with a code is closed for 10 minutes, and Telegram tells you when the password was right and the code wasn't (with sign-in notifications on, at most once in 10 minutes per address) — a sign that the password should be changed. Turning the code on now asks for the panel password.

- **Your own AmneziaWG server stays up to date.** If the panel's installer set up its own AmneziaWG server in a container, that container was never updated and ran on a 2023 system without security fixes. It is now built on a current system with the same AmneziaWG as the panel, and **every update of the panel updates it too**. Keys, clients and the port stay the same, configs don't change; VPN pauses for a few seconds during the update. If the new container doesn't start, the old one is started again. A server made by the AmneziaVPN app or a server on the host is not touched.

- **A safer build.** Programs from other projects (AmneziaWG and the SOCKS5 tunnel) and the base systems are now taken by their exact fingerprint, not by version name: if someone swapped the code behind a version name, the build would stop instead of putting that code into a release. The SOCKS5 tunnel is updated to 2.19.3, with fixes from ten releases (UDP among them); the newest 2.20.0 is held back because in our tests it slowed down SOCKS5 exits with a speed limit. AmneziaWG (amneziawg-go) is updated to v3.1.20261116: only fixes, among them safer handling of wrong junk-packet settings.

- **The client's name stays with you.** The name you give a client is no longer shown to the client: their personal page starts with **Your access**, and the config file and the connection name inside the `vpn://` link are 8 digits of that client (the same every time, e.g. `48203917.conf`) — in the panel, in the bot and on the personal page alike. A client who imports the config again gets a second connection with the digits; the old one can be deleted, both are the same access. **Show config** on the personal page and in the client window shows the whole config inside the card, long lines wrapped (copying and downloading give it unchanged).

- **Clients can check their access in your Telegram bot.** Every client now has an invitation to the bot (client window → **Connect**). Whoever opens it sees in a private chat with the bot the same as on their personal page — online or not, traffic, end date and limit — and can get their config there (QR code, file and `vpn://` link). Nothing else of the panel is visible to them; the bot writes to them first only with reminders (next item). The switch is **System → Telegram → Clients can check their access in the bot**: on by default; if your bot only sent notifications so far, it stays off until you turn it on. The bot's command menu now shows only in your own chat with it.

- **Reminders to clients in the bot.** A client who opened the invitation now gets a message in the bot 3 days before the end date, at 90% of the traffic limit, when access is turned off by the end date or limit, and when a monthly limit lets it on again — you don't have to warn everyone yourself. **System → Telegram → Remind clients in the bot about the end date and limit**, on by default.

- **The personal link is there from the start.** A new client gets its personal link right away, so you don't have to create it. The link and the bot invitation sit together in the client window under **Connect**, next to the QR code and `vpn://`. **Renew link and invitation** replaces both: the old ones stop working, and a Telegram connected with the old invitation is disconnected — use it when a link got to the wrong person. Clients made before 1.22.0 get a **Create link** button.

- **Your own DNS for a list of sites.** A domain rule can now have its own DNS server (**Routing → rule → Own DNS for these sites**, one or two IPv4 addresses): names from its lists are asked there, the same way the rule's sites go, and everything else goes to your usual DNS. For example, Russian sites direct through Yandex DNS (`77.88.8.8`), Chinese ones through Alibaba (`223.5.5.5`), Iranian ones through an Iranian DNS, and the rest through the exit to `1.1.1.1`. The local DNS learns only about local sites. It works with **DNS on the server** turned on, and only for site (domain) lists: for address lists the address is known only after the DNS answer. For a cascade, **Server → DNS on the server → Why and how to set it up** has a button that adds such a rule in one press: the zone of the server's country (for example, `.ru`) goes Direct with a local DNS, and you only check and save it. The server's own address can't be entered as an own DNS: it would do nothing.

- **The port of a server in a container can be changed.** **Server → Port (UDP)** now works for a server in a Docker container too — the panel's own and the one the AmneziaVPN app made. The panel creates the container anew with the same keys, clients and files and the new port; VPN pauses for a few seconds, and clients need a new config. If the server doesn't start on the new port (for example, the port is taken), the old container is started again. Clients created in the AmneziaVPN app keep their key only on the device: after the change they need the new port in their config, or a new client from the panel — the panel warns about this before the change. If the change is cut off midway (the panel or the server goes down), the panel brings the old container back by itself.

- **SOCKS5 exits are checked from where they really work.** The panel checked a SOCKS5 proxy from the server itself, while the clients' traffic goes from the AmneziaWG server's network. A proxy on the server's own address showed as working although clients couldn't use it, and the other way round. Now the check goes the same way as the clients' traffic.

- **Telegram notifications no longer go silent when a group becomes a supergroup.** Telegram gives such a group a new number; the panel now picks it up by itself.

- **Big network lists no longer eat the memory.** A list of networks from a link with hundreds of thousands of lines took hundreds of megabytes while being updated; on a server with 1 GB of memory that could stop the panel. It now takes a few dozen megabytes.

- **Faster when many clients end at once.** If a thousand clients had the same end date, the panel turned them off one by one for about 25 seconds, and you couldn't add a client meanwhile. Now it is one step.

- **A clear message when two panels share one bot.** If another program (usually a second panel with the same bot) reads your bot, commands went to one or the other at random. The Telegram settings now say so and suggest a separate bot for each panel.

- **The bot writes errors in words.** Instead of internal codes like `srv.subnet_full` the bot now writes the same sentence the panel shows, in the bot's language.

- **Small fixes in Telegram.** **Find** next to the Chat ID now works even when the bot already reads its messages (before, it said nothing was found). In a group the bot answers only commands, a mention of it or a reply to its message, not every phrase. If the panel opens only through an SSH tunnel, **Panel** in the bot now gives the command with your login and SSH port, like the installer does, instead of always `root` (after this update, the installer remembers the port). The picture of the bot's menu is now on a white background and taller. A client's card in the bot starts with "Your access" instead of the name you gave the client, and its lines have icons.

- **Small things in the interface.** A rule moves to another place by picking its number, not only with ↑ ↓. **Refresh lists every, h** moved from **System → Settings** to the lists on the **Routing** tab, next to what it is about. On a phone the buttons of a list row no longer stick out past the right edge of the screen. The domain list window shows that a whole zone works (`.com`, `.net`) and keeps only what matters for the rules to work. The explanation under **DNS on the server** is short and says what to set for a cascade. Terms are made consistent: the server and its container are named the same way everywhere, and the hints in empty lists of clients and exits say what to do right here. An old or mistyped personal link now says plainly that it no longer works; an empty port or refresh period is no longer saved by mistake. The save button on the **Routing** and **Server** tabs now sits at the top, right under the tab names, while there is something to save.

- **The server's name in the browser tab.** With several servers open you no longer have to look at the address bar: the tab shows the server's address, or a name you give it in **System → Settings → Server name**. Thanks to @MacSergey (#38).

- **Day/night button.** A sun or moon button in the header switches the panel between light and dark; the browser remembers your choice, and the client's personal page follows it too. Without a choice the panel follows your system, as before. Thanks to @paris19891 for the idea (#38).

- **Even rows on a phone.** In the client list on a phone, the exit sits at the right edge in every row, like the month's traffic, instead of shifting from row to row.

## Что изменилось

- **Вход по коду надёжнее.** Если кто-то знает пароль панели, неверные коды из приложения теперь считаются со всех адресов вместе: после 10 неверных кодов вход по коду закрыт на 10 минут, а Telegram сообщает вам, когда пароль был верный, а код — нет (если уведомления о входе включены, не чаще раза в 10 минут с одного адреса): это знак, что пароль пора сменить. Теперь он собирается на свежей системе, с той же AmneziaWG, что и панель, и **обновляется при каждом обновлении панели**. Ключи, клиенты и порт остаются прежними, конфиги не меняются; на время обновления VPN прерывается на несколько секунд. Если новый контейнер не запустится, снова запускается прежний. Сервер, поставленный приложением AmneziaVPN, и сервер на самом VPS это не затрагивает.

- **Сборка надёжнее.** Программы других проектов (AmneziaWG и туннель для SOCKS5) и основы систем теперь берутся по точному отпечатку, а не по названию версии: если бы кто-то подменил код под названием версии, сборка остановилась бы, а не взяла этот код в выпуск. Туннель для SOCKS5 обновлён до 2.19.3 — с исправлениями десяти выпусков (в том числе для UDP); самая новая 2.20.0 пока не взята: в наших тестах она замедляла выходы SOCKS5 с ограничением скорости. AmneziaWG (amneziawg-go) обновлён до v3.1.20261116: только исправления, среди них — защита от неверных настроек мусорных пакетов.

- **Имя клиента остаётся у вас.** Имя, которое вы даёте клиенту, ему больше не показывается: его личная страница начинается с **«Ваш доступ»**, а файл конфига и название подключения внутри ссылки `vpn://` — 8 цифр этого клиента (каждый раз те же, например `48203917.conf`) — и в панели, и в боте, и на личной странице. Если клиент импортирует конфиг заново, у него появится второе подключение с цифрами; старое можно удалить, это один и тот же доступ. **«Показать конфиг»** на личной странице и в окне клиента показывает конфиг целиком внутри карточки, длинные строки переносятся (копируется и скачивается он без изменений).

- **Клиенты могут смотреть свой доступ в вашем боте Telegram.** У каждого клиента теперь есть приглашение в бота (окно клиента → **«Подключение»**). Тот, кто его откроет, видит в личном чате с ботом то же, что на своей личной странице: в сети ли, трафик, срок и лимит, — и может получить там свой конфиг (QR-код, файл и ссылку `vpn://`). Больше ничего из панели ему не видно; сам бот пишет ему только напоминания (следующий пункт). Включается в **«Система» → «Telegram» → «Клиенты могут смотреть свой доступ в боте»**: по умолчанию включено; если ваш бот до сих пор только присылал уведомления, это остаётся выключенным, пока вы не включите. Меню команд бота теперь видно только в вашем собственном чате с ним.

- **Напоминания клиентам в боте.** Клиент, открывший приглашение, теперь получает сообщение в боте за 3 дня до конца срока, при 90% лимита трафика, когда доступ выключился из-за срока или лимита и когда месячный лимит снова его включил, — предупреждать каждого самому не нужно. **«Система» → «Telegram» → «Напоминать клиентам в боте о сроке и лимите»**, по умолчанию включено.

- **Личная ссылка — сразу.** У нового клиента личная ссылка появляется сразу, создавать её не нужно. Ссылка и приглашение в бота — вместе в окне клиента, в **«Подключении»**, рядом с QR-кодом и `vpn://`. **«Обновить ссылку и приглашение»** меняет обе: прежние перестают работать, а Telegram, подключённый по прежнему приглашению, отключается, — это на случай, если ссылка попала не тому человеку. У клиентов, созданных до 1.22.0, — кнопка **«Создать ссылку»**.

- **Свой DNS для списка сайтов.** У правила по сайтам теперь может быть свой DNS-сервер (**«Маршрутизация» → правило → «Свой DNS для этих сайтов»**, один-два IPv4): имена из его списков спрашиваются у него — тем же путём, что идут сайты правила, — а всё остальное у вашего обычного DNS. Например, российские сайты — напрямую через DNS Яндекса (`77.88.8.8`), китайские — через Alibaba (`223.5.5.5`), иранские — через иранский DNS, остальное — через выход у `1.1.1.1`. Местный DNS узнаёт только о местных сайтах. Работает при включённом **«DNS на сервере»** и только для списков сайтов (доменов): у списка адресов адрес известен только после ответа DNS. Для каскада в **«Сервер» → «DNS на сервере» → «Зачем это и как настроить»** есть кнопка, которая добавляет такое правило одним нажатием: зона страны сервера (например, `.ru`) — напрямую, с местным DNS; остаётся проверить и сохранить. Адрес самого сервера в «Свой DNS» вписать нельзя: он ничего не дал бы.

- **Порт сервера в контейнере теперь можно поменять.** **«Сервер» → «Порт (UDP)»** работает и для сервера в контейнере Docker — и своего контейнера панели, и созданного приложением AmneziaVPN. Панель создаёт контейнер заново с теми же ключами, клиентами и файлами и новым портом; VPN прерывается на несколько секунд, клиентам нужен новый конфиг. Если сервер не запустился на новом порту (например, порт занят), снова запускается прежний контейнер. У клиентов, созданных в приложении AmneziaVPN, ключ есть только на устройстве: после смены им нужен новый порт в их конфиге или новый клиент из панели — панель предупреждает об этом до смены. Если смену прервут посреди (упадёт панель или выключится сервер), панель сама вернёт прежний контейнер.

- **Выходы SOCKS5 проверяются оттуда, откуда они работают.** Панель проверяла прокси SOCKS5 с самого сервера, а трафик клиентов идёт из сети сервера AmneziaWG. Прокси на собственном адресе сервера показывался рабочим, хотя клиентам он был недоступен, и наоборот. Теперь проверка идёт тем же путём, что и трафик клиентов.

- **Уведомления Telegram больше не замолкают, когда группа становится супергруппой.** Telegram даёт такой группе новый номер; панель теперь сама его подхватывает.

- **Большие списки сетей больше не съедают память.** Список сетей по ссылке на сотни тысяч строк при обновлении занимал сотни мегабайт; на сервере с 1 ГБ памяти это могло остановить панель. Теперь — несколько десятков мегабайт.

- **Быстрее, когда срок кончается у многих сразу.** Если у тысячи клиентов один срок, панель отключала их по одному около 25 секунд, и добавить клиента в это время было нельзя. Теперь — одним шагом.

- **Понятное сообщение, когда у двух панелей один бот.** Если вашего бота читает другая программа (обычно вторая панель с тем же ботом), команды доставались то одной, то другой. Теперь об этом говорят настройки Telegram и советуют завести каждой панели свой бот.

- **Бот пишет ошибки словами.** Вместо внутренних кодов вроде `srv.subnet_full` бот пишет ту же фразу, что и панель, на языке бота.

- **Мелочи в Telegram.** **«Найти»** рядом с Chat ID теперь работает, даже когда бот уже читает свои сообщения (раньше писал, что ничего не найдено). В группе бот отвечает только на команды, на упоминание и на ответ на его сообщение, а не на каждую фразу. Если панель открывается только через SSH-туннель, **«Панель»** в боте теперь даёт команду с вашим именем для входа и портом SSH, как установщик, а не всегда `root` (порт установщик запоминает при этом обновлении). Картинка меню бота — теперь на белом фоне и выше. Карточка клиента в боте начинается с «Ваш доступ», а не с имени, которое вы дали клиенту, и строки в ней со значками.

- **Мелочи в интерфейсе.** Правило переносится на другое место выбором его номера, не только стрелками ↑ ↓. **«Обновлять списки каждые, ч»** переехало из **«Система» → «Настройки»** к спискам на вкладке **«Маршрутизация»**, рядом с тем, о чём оно. На телефоне кнопки строки списка больше не вылезают за правый край экрана. Окно списка доменов подсказывает, что можно указать целую зону (`.net`, `.ru`), и оставляет только то, что важно для работы правил. Пояснение под **«DNS на сервере»** стало коротким и говорит, что задать для каскада. Термины выровнены: сервер и его контейнер везде называются одинаково, а подсказки в пустых списках клиентов и выходов говорят, что сделать прямо здесь. Старая или неверная личная ссылка теперь прямо говорит, что больше не действует; пустой порт или период обновления списков больше не сохраняются по ошибке. Кнопка сохранения на вкладках **«Маршрутизация»** и **«Сервер»** теперь стоит наверху, сразу под названиями вкладок, пока есть что сохранить.

- **Название сервера во вкладке браузера.** Когда открыто несколько серверов, больше не нужно смотреть в адресную строку: во вкладке — адрес сервера или название, которое вы ему дали в **«Система» → «Настройки» → «Название сервера»**. Спасибо @MacSergey (#38).

- **Кнопка «день/ночь».** Кнопка с солнцем или луной в шапке переключает панель между светлой и тёмной темой; браузер запоминает выбор, и личная страница клиента тоже следует ему. Без выбора панель, как раньше, следует теме системы. Спасибо @paris19891 за идею (#38).

- **Ровные строки на телефоне.** В списке клиентов на телефоне выход в каждой строке стоит у правого края, как трафик за месяц, а не «прыгает» от строки к строке.

- **验证码登录更安全。** 如果有人知道面板密码，来自所有地址的错误验证码现在会合并计数：10 次错误后，验证码登录关闭 10 分钟；密码正确而验证码错误时，Telegram 会通知你（需开启登录通知，同一地址 10 分钟内最多一次）——这说明该更换密码了。开启验证码登录现在需要输入面板密码。

- **你自己的 AmneziaWG 服务器保持最新。** 如果面板安装程序把自己的 AmneziaWG 服务器装在容器中，这个容器以前从未更新，一直运行在没有安全修复的 2023 年系统上。现在它基于最新系统构建，使用与面板相同的 AmneziaWG，并且 **每次更新面板时都会一起更新**。密钥、客户端和端口保持不变，配置也不变；更新期间 VPN 会中断几秒。如果新容器无法启动，会重新启动旧容器。由 AmneziaVPN 应用创建的服务器和直接装在主机上的服务器不受影响。

- **构建更安全。** 其他项目的程序（AmneziaWG 和 SOCKS5 隧道）以及基础系统现在按精确指纹获取，而不是按版本名：如果有人替换了某个版本名背后的代码，构建会停止，而不会把这些代码带进发布版。SOCKS5 隧道已更新到 2.19.3，包含十个版本的修复（其中有 UDP 的修复）；最新的 2.20.0 暂不采用：在我们的测试中，它会让限速的 SOCKS5 出口变慢。AmneziaWG（amneziawg-go）已更新到 v3.1.20261116：只有修复，其中包括更安全地处理错误的垃圾包设置。

- **客户端的名字只留给你。** 你给客户端起的名字不再显示给客户端：其个人页面以 **你的访问** 开头，配置文件以及 `vpn://` 链接中的连接名称为该客户端的 8 位数字（每次相同，例如 `48203917.conf`）——在面板、机器人和个人页面中都是如此。客户端重新导入配置时会多出一个以数字命名的连接；旧的可以删除，两者是同一个访问。个人页面和客户端窗口中的 **显示配置** 会在卡片内完整显示配置，长行自动换行（复制和下载的内容不变）。

- **客户端可以在你的 Telegram 机器人中查看自己的访问。** 现在每个客户端都有一个机器人邀请（客户端窗口 → **连接**）。打开邀请的人可以在与机器人的私聊中看到与其个人页面相同的内容——是否在线、流量、到期时间和限额——并能在那里获取自己的配置（二维码、文件和 `vpn://` 链接）。面板的其他内容对其不可见；机器人只会主动发送提醒（见下一条）。开关在 **系统 → Telegram → 客户端可以在机器人中查看自己的访问**：默认开启；如果你的机器人此前只用于发送通知，则保持关闭，直到你手动开启。机器人的命令菜单现在只在你自己与它的聊天中显示。

- **在机器人中提醒客户端。** 打开邀请的客户端现在会在机器人中收到消息：到期前 3 天、流量限额用掉 90% 时、因到期或限额被停用时，以及按月限额重新启用时——你不必再逐个提醒。**系统 → Telegram → 在机器人中提醒客户端到期时间和限额**，默认开启。

- **个人链接一开始就有。** 新客户端创建后立即拥有个人链接，无需再手动创建。链接和机器人邀请一起位于客户端窗口的 **连接** 中，紧挨二维码和 `vpn://`。**更新链接和邀请** 会同时更换两者：旧的将失效，用旧邀请连接的 Telegram 也会被断开——适用于链接落到了不该给的人手里时。1.22.0 之前创建的客户端会显示 **创建链接** 按钮。

- **网站列表的专用 DNS。** 按网站的规则现在可以有自己的 DNS 服务器（**路由 → 规则 → 这些网站的专用 DNS**，一到两个 IPv4）：其列表中的名称向它查询，与规则中的网站走同一路径，其余名称仍向常用 DNS 查询。例如，中国网站直连并经阿里 DNS（`223.5.5.5`）解析，俄罗斯网站经 Yandex DNS（`77.88.8.8`），其余经由出口向 `1.1.1.1` 查询。本地 DNS 只会知道本地网站。需开启 **服务器上的 DNS**，且只适用于网站（域名）列表：地址列表要等 DNS 回答后才知道地址。 对于级联，**服务器 → 服务器上的 DNS → 作用与设置方法** 中有一个按钮，一键添加这样的规则：服务器所在国家的域名区（例如 `.cn`）直连并使用本地 DNS，你只需检查并保存。不能把服务器自身的地址填为专用 DNS：那样不起任何作用。

- **容器中服务器的端口现在可以更改。** **服务器 → 端口（UDP）** 现在也适用于 Docker 容器中的服务器——无论是面板自己的容器，还是 AmneziaVPN 应用创建的容器。面板会用相同的密钥、客户端和文件以及新端口重新创建容器；VPN 会中断几秒钟，客户端需要新的配置。如果服务器无法在新端口上启动（例如端口已被占用），会重新启动原来的容器。在 AmneziaVPN 应用中创建的客户端，密钥只保存在设备上：更换后需要在其配置中改为新端口，或从面板获取新客户端——面板会在更换前提醒这一点。 如果更改中途被打断（面板或服务器宕机），面板会自动恢复原来的容器。

- **SOCKS5 出口从它真正工作的地方检查。** 面板以前从服务器本身检查 SOCKS5 代理，而客户端的流量是从 AmneziaWG 服务器的网络发出的。位于服务器自身地址上的代理会显示为正常，但客户端却无法使用，反之亦然。现在检查与客户端流量走同一条路。

- **群组升级为超级群组后，Telegram 通知不再静默中断。** Telegram 会给这样的群组一个新编号；面板现在会自动采用。

- **大型网络列表不再占满内存。** 一个通过链接获取、多达几十万行的网络列表在更新时会占用数百兆内存；在 1 GB 内存的服务器上，这可能导致面板停止。现在只需几十兆。

- **许多客户端同时到期时更快。** 如果一千个客户端的到期时间相同，面板会逐个停用它们，约 25 秒，期间无法添加客户端。现在只需一步。

- **两个面板共用一个机器人时给出明确提示。** 如果另一个程序（通常是使用同一机器人的第二个面板）也在读取你的机器人，命令会随机落到其中一方。现在 Telegram 设置会说明这一点，并建议每个面板使用自己的机器人。

- **机器人用文字说明错误。** 机器人不再发送 `srv.subnet_full` 之类的内部代码，而是用机器人的语言发送与面板相同的句子。

- **Telegram 的小修复。** Chat ID 旁的 **查找** 现在即使机器人已在读取自己的消息时也能工作（以前会说什么都没找到）。在群组中，机器人只回应命令、对它的提及或对它消息的回复，而不是每句话。如果面板只能通过 SSH 隧道打开，机器人中的 **面板** 现在会像安装程序一样给出带有您的登录用户名和 SSH 端口的命令，而不总是 `root`（安装程序会在这次更新时记下端口）。机器人菜单的图片现在是白色背景，而且更高。机器人中的客户端卡片以“你的访问”开头，而不是你给客户端起的名字，各行都带有图标。

- **界面小改进。** 选择规则的编号即可把它移到其他位置，不必只用 ↑ ↓。**列表更新间隔（小时）** 从 **系统 → 设置** 移到了 **路由** 标签页的列表旁边。在手机上，列表行的按钮不再超出屏幕右边缘。域名列表窗口会提示可以填写整个域名区（`.net`、`.cn`），说明只保留规则正常工作所需的要点。**服务器上的 DNS** 下的说明更简短，并写明级联时需要设置什么。术语已统一：服务器及其容器在各处的叫法一致，空的客户端和出口列表中的提示会说明在这里该做什么。 旧的或错误的个人链接现在会直接提示已失效；空的端口或列表更新间隔不会再被误存。 **路由** 和 **服务器** 标签页的保存按钮现在位于顶部、紧挨标签名称下方，只要有未保存的内容就一直显示。

- **浏览器标签页中的服务器名称。** 同时打开多个服务器时，不必再看地址栏：标签页显示服务器地址，或你在 **系统 → 设置 → 服务器名称** 中为它取的名称。感谢 @MacSergey（#38）。

- **日/夜按钮。** 页眉中的太阳或月亮按钮可在浅色和深色主题之间切换；浏览器会记住你的选择，客户端的个人页面也随之变化。未选择时，面板仍像以前一样跟随系统主题。感谢 @paris19891 的建议（#38）。

- **手机上每行对齐。** 在手机上的客户端列表中，出口在每一行都靠右对齐，与本月流量一致，不再逐行错位。

## تغییرها

- **ورود با کد امن‌تر.** اگر کسی گذرواژهٔ پنل را بداند، کدهای نادرست برنامه اکنون از همهٔ نشانی‌ها با هم شمرده می‌شوند: پس از ۱۰ کد نادرست، ورود با کد ۱۰ دقیقه بسته می‌شود و وقتی گذرواژه درست و کد نادرست بود، پیامی در تلگرام می‌گیرید (اگر اعلان‌های ورود روشن باشد، از هر نشانی حداکثر یک بار در ۱۰ دقیقه) — نشانه‌ای که باید گذرواژه را عوض کنید. روشن کردن ورود با کد اکنون گذرواژهٔ پنل را می‌خواهد.

- **سرور AmneziaWG خودتان به‌روز می‌ماند.** اگر نصب‌کنندهٔ پنل سرور AmneziaWG خودش را در یک کانتینر نصب کرده بود، آن کانتینر هرگز به‌روز نمی‌شد و روی سیستمی از ۲۰۲۳ بدون وصله‌های امنیتی کار می‌کرد. اکنون روی سیستمی تازه و با همان AmneziaWG پنل ساخته می‌شود و **با هر به‌روزرسانی پنل به‌روز می‌شود**. کلیدها، کاربران و درگاه همان می‌مانند و پیکربندی‌ها عوض نمی‌شوند؛ در زمان به‌روزرسانی VPN چند ثانیه قطع می‌شود. اگر کانتینر تازه بالا نیاید، کانتینر قبلی دوباره روشن می‌شود. سروری که برنامهٔ AmneziaVPN ساخته یا سروری که مستقیم روی میزبان است تغییری نمی‌کند.

- **ساخت امن‌تر.** برنامه‌های پروژه‌های دیگر (AmneziaWG و تونل SOCKS5) و سیستم‌های پایه اکنون با اثر انگشت دقیقشان گرفته می‌شوند، نه با نام نسخه: اگر کسی کد پشت یک نام نسخه را عوض کند، ساخت متوقف می‌شود و آن کد وارد انتشار نمی‌شود. تونل SOCKS5 به 2.19.3 به‌روز شده و اصلاحات ده نسخه (از جمله برای UDP) را دارد؛ تازه‌ترین نسخه، 2.20.0، فعلاً گرفته نشده: در آزمایش‌های ما خروجی‌های SOCKS5 با محدودیت سرعت را کند می‌کرد. AmneziaWG (<bdi>amneziawg-go</bdi>) به <bdi>v3.1.20261116</bdi> به‌روز شده است: فقط اصلاحات، از جمله برخورد امن‌تر با تنظیمات نادرست بسته‌های بی‌معنا.

- **نام کاربر نزد شما می‌ماند.** نامی که به کاربر می‌دهید دیگر به خود او نشان داده نمی‌شود: صفحهٔ شخصی‌اش با **دسترسی شما** شروع می‌شود و فایل پیکربندی و نام اتصال درون لینک <bdi>`vpn://`</bdi> هشت رقمِ همان کاربر است (هر بار همان، مثلاً <bdi>`48203917.conf`</bdi>) — در پنل، در ربات و در صفحهٔ شخصی. اگر کاربر پیکربندی را دوباره وارد کند، اتصال دومی با رقم‌ها پیدا می‌شود؛ قبلی را می‌شود پاک کرد، هر دو یک دسترسی‌اند. **نمایش پیکربندی** در صفحهٔ شخصی و پنجرهٔ کلاینت پیکربندی را کامل درون کارت نشان می‌دهد و سطرهای بلند شکسته می‌شوند (کپی و دانلود بدون تغییر است).

- **کلاینت‌ها می‌توانند دسترسی خود را در ربات تلگرام شما ببینند.** اکنون هر کلاینت یک دعوت به ربات دارد (پنجرهٔ کلاینت ← **اتصال**). هر کس آن را باز کند، در گفت‌وگوی خصوصی با ربات همان چیزی را می‌بیند که در صفحهٔ شخصی‌اش هست — آنلاین است یا نه، ترافیک، مهلت و سقف — و می‌تواند پیکربندی‌اش را همان‌جا بگیرد (کد QR، فایل و پیوند <bdi>`vpn://`</bdi>). چیز دیگری از پنل برایش دیده نمی‌شود؛ ربات خودش فقط یادآوری می‌فرستد (مورد بعدی). کلید آن در **سیستم ← تلگرام ← کلاینت‌ها می‌توانند دسترسی خود را در ربات ببینند** است: به‌طور پیش‌فرض روشن است؛ اگر ربات شما تا حالا فقط اعلان می‌فرستاد، خاموش می‌ماند تا خودتان روشنش کنید. منوی فرمان‌های ربات اکنون فقط در گفت‌وگوی خود شما با آن دیده می‌شود.

- **یادآوری به کلاینت‌ها در ربات.** کلاینتی که دعوت را باز کرده، اکنون در ربات پیام می‌گیرد: ۳ روز پیش از پایان مهلت، وقتی ۹۰٪ سقف ترافیک مصرف شد، وقتی دسترسی به‌خاطر مهلت یا سقف خاموش شد و وقتی سقف ماهانه دوباره روشنش کرد — دیگر لازم نیست خودتان به هر کس خبر بدهید. **سیستم ← تلگرام ← یادآوری مهلت و سقف به کلاینت‌ها در ربات**، به‌طور پیش‌فرض روشن.

- **لینک شخصی از همان ابتدا.** کاربر تازه بی‌درنگ لینک شخصی دارد و لازم نیست آن را بسازید. لینک و دعوت ربات با هم در پنجرهٔ کلاینت، بخش **اتصال**، کنار کد QR و <bdi>`vpn://`</bdi> هستند. **تازه کردن پیوند و دعوت** هر دو را عوض می‌کند: قبلی‌ها دیگر کار نمی‌کنند و تلگرامی که با دعوت قبلی وصل شده جدا می‌شود — برای وقتی که لینک به دست کس دیگری افتاده است. کاربرانی که پیش از 1.22.0 ساخته شده‌اند دکمهٔ **ساخت لینک** دارند.

- **DNS ویژه برای فهرست سایت‌ها.** قانون سایت‌ها اکنون می‌تواند سرور DNS خودش را داشته باشد (**مسیریابی ← قانون ← DNS ویژهٔ این سایت‌ها**، یک یا دو IPv4): نام‌های فهرست‌هایش از همان سرور پرسیده می‌شوند، از همان راهی که سایت‌های قانون می‌روند، و بقیه از DNS معمول شما. مثلاً سایت‌های ایرانی مستقیم و با DNS ایرانی، و بقیه از راه خروجی از <bdi>`1.1.1.1`</bdi>. DNS محلی فقط از سایت‌های محلی باخبر می‌شود. با روشن بودن **DNS روی سرور** کار می‌کند و فقط برای فهرست سایت‌ها (دامنه‌ها): در فهرست نشانی‌ها، نشانی تنها پس از پاسخ DNS معلوم است. برای آبشار، در **سرور ← DNS روی سرور ← چرا و چطور تنظیم کنیم** دکمه‌ای هست که چنین قانونی را با یک بار زدن می‌افزاید: منطقهٔ کشور سرور (مثلاً <bdi>`.ir`</bdi>) مستقیم و با DNS محلی؛ فقط بررسی و ذخیره کنید. نشانی خود سرور را نمی‌شود به‌عنوان DNS ویژه نوشت: کاری نمی‌کرد.

- **درگاه سرور درون کانتینر را می‌شود عوض کرد.** **سرور ← درگاه (UDP)** اکنون برای سرور درون کانتینر Docker هم کار می‌کند — هم کانتینر خود پنل و هم کانتینری که برنامهٔ AmneziaVPN ساخته است. پنل کانتینر را با همان کلیدها، کاربران و فایل‌ها و درگاه تازه از نو می‌سازد؛ VPN چند ثانیه قطع می‌شود و کاربران پیکربندی تازه لازم دارند. اگر سرور روی درگاه تازه راه نیفتد (مثلاً درگاه اشغال باشد)، کانتینر قبلی دوباره راه‌اندازی می‌شود. کلید کاربرانی که در برنامهٔ AmneziaVPN ساخته شده‌اند فقط روی دستگاه است: پس از تغییر، درگاه تازه باید در پیکربندی‌شان نوشته شود یا از پنل کاربر تازه بگیرند — پنل پیش از تغییر این را هشدار می‌دهد. اگر تغییر در میانه قطع شود (پنل یا سرور از کار بیفتد)، پنل خودش کانتینر قبلی را برمی‌گرداند.

- **خروجی‌های SOCKS5 از همان جایی بررسی می‌شوند که واقعاً کار می‌کنند.** پنل پراکسی SOCKS5 را از خود سرور بررسی می‌کرد، در حالی که ترافیک کاربران از شبکهٔ سرور AmneziaWG می‌رود. پراکسی روی نشانی خود سرور کارا نشان داده می‌شد، هرچند کاربران نمی‌توانستند از آن استفاده کنند، و برعکس. اکنون بررسی از همان راه ترافیک کاربران انجام می‌شود.

- **اعلان‌های تلگرام وقتی گروه به سوپرگروه تبدیل می‌شود دیگر خاموش نمی‌شوند.** تلگرام به چنین گروهی شمارهٔ تازه می‌دهد؛ پنل اکنون خودش آن را برمی‌دارد.

- **فهرست‌های بزرگ شبکه دیگر حافظه را نمی‌بلعند.** فهرست شبکه‌ای از یک پیوند با صدها هزار سطر هنگام به‌روزرسانی صدها مگابایت می‌گرفت؛ روی سروری با ۱ گیگابایت حافظه این می‌توانست پنل را متوقف کند. اکنون چند ده مگابایت.

- **سریع‌تر وقتی مهلت بسیاری از کاربران با هم تمام می‌شود.** اگر هزار کاربر یک مهلت داشتند، پنل آن‌ها را یکی‌یکی حدود ۲۵ ثانیه خاموش می‌کرد و در این مدت نمی‌شد کاربر تازه افزود. اکنون یک گام است.

- **پیام روشن وقتی دو پنل یک ربات دارند.** اگر برنامهٔ دیگری (معمولاً پنل دومی با همان ربات) ربات شما را بخواند، فرمان‌ها گاهی به یکی و گاهی به دیگری می‌رسیدند. اکنون تنظیمات تلگرام این را می‌گویند و پیشنهاد می‌کنند هر پنل ربات خودش را داشته باشد.

- **ربات خطاها را با کلمه می‌نویسد.** ربات به‌جای کدهای درونی مانند <bdi>`srv.subnet_full`</bdi> همان جمله‌ای را می‌نویسد که پنل نشان می‌دهد، به زبان ربات.

- **اصلاحات کوچک در تلگرام.** **پیدا کن** کنار Chat ID اکنون حتی وقتی ربات خودش پیام‌هایش را می‌خواند کار می‌کند (پیش‌تر می‌گفت چیزی پیدا نشد). ربات در گروه فقط به فرمان‌ها، به نام بردن از آن و به پاسخ به پیامش جواب می‌دهد، نه به هر جمله. اگر پنل فقط از راه تونل SSH باز می‌شود، **پنل** در ربات اکنون مانند نصب‌کننده فرمانی با نام کاربری ورود شما و درگاه SSH می‌دهد، نه همیشه <bdi>`root`</bdi> (نصب‌کننده درگاه را در همین به‌روزرسانی به خاطر می‌سپارد). تصویر منوی ربات اکنون پس‌زمینهٔ سفید دارد و بلندتر است. کارت کاربر در ربات با «دسترسی شما» شروع می‌شود، نه با نامی که به کاربر داده‌اید، و سطرهایش نماد دارند.

- **ریزه‌کاری‌های رابط.** قانون با انتخاب شماره‌اش به جای دیگر می‌رود، نه فقط با ↑ ↓. **به‌روزرسانی فهرست‌ها هر چند ساعت** از **سیستم ← تنظیمات** به کنار فهرست‌ها در زبانهٔ **مسیریابی** رفته است. روی گوشی دکمه‌های ردیف فهرست دیگر از لبهٔ صفحه بیرون نمی‌زنند. پنجرهٔ فهرست دامنه‌ها نشان می‌دهد که می‌شود یک منطقهٔ کامل داد (<bdi>`.net`</bdi>، <bdi>`.ir`</bdi>) و فقط نکته‌های لازم برای کار قانون‌ها را نگه می‌دارد. توضیح زیر **DNS روی سرور** کوتاه شده و می‌گوید برای آبشار چه باید تنظیم کرد. واژه‌ها یکدست شده‌اند: سرور و کانتینرش همه‌جا یک‌جور نامیده می‌شوند و راهنمای فهرست‌های خالی کلاینت‌ها و خروجی‌ها می‌گوید همین‌جا چه باید کرد. لینک شخصی قدیمی یا نادرست اکنون به‌روشنی می‌گوید که دیگر معتبر نیست؛ درگاه یا دورهٔ به‌روزرسانی خالی دیگر به اشتباه ذخیره نمی‌شود. دکمهٔ ذخیره در زبانه‌های **مسیریابی** و **سرور** اکنون بالا، درست زیر نام زبانه‌ها، می‌ماند تا وقتی چیزی برای ذخیره هست.

- **نام سرور در زبانهٔ مرورگر.** وقتی چند سرور باز است، دیگر لازم نیست به نوار نشانی نگاه کنید: زبانه نشانی سرور یا نامی را نشان می‌دهد که در **سیستم ← تنظیمات ← نام سرور** به آن داده‌اید. با سپاس از @MacSergey (&lrm;#38&lrm;).

- **دکمهٔ روز/شب.** دکمهٔ خورشید یا ماه در سربرگ پنل را میان پوستهٔ روشن و تیره جابه‌جا می‌کند؛ مرورگر انتخاب شما را به خاطر می‌سپارد و صفحهٔ شخصی کاربر هم از آن پیروی می‌کند. بدون انتخاب، پنل مثل قبل از پوستهٔ سیستم پیروی می‌کند. با سپاس از @paris19891 برای این ایده (&lrm;#38&lrm;).

- **ردیف‌های مرتب روی گوشی.** در فهرست کاربران روی گوشی، خروجی در هر ردیف مثل ترافیک ماه در لبهٔ کناری قرار می‌گیرد و دیگر از ردیفی به ردیف دیگر جابه‌جا نمی‌شود.
