## What's changed

- **Domain rules to any exit.** A list of sites can now go through an AmneziaWG exit, directly or to Block, not only through a SOCKS5 proxy. Through SOCKS5 the proxy still gets the site name and finds the address itself; through AmneziaWG and Direct the connection goes to the address the device got from its own DNS, so turn on DNS on the server if your ISP spoofs DNS. The exit window lets you set sites and lists for AmneziaWG exits too. A domain rule that changes nothing (it leads where everything else goes) no longer sends all of a client's web traffic through the domain handler.

- **HTTP/3 (QUIC) keeps working with domain rules.** Before, clients with domain rules lost HTTP/3 for every site. Now the server reads the site name from the first QUIC packets too: a listed site goes through its AmneziaWG exit or directly over HTTP/3, a site behind a SOCKS5 exit is moved to HTTPS (the proxy gets the name there) unless you let QUIC through that proxy, and all other sites keep HTTP/3. On servers whose kernel can't queue packets (some OpenVZ/LXC) it stays as before, and the panel says so.

- **DNS on the server follows the domain rules.** With DNS on the server turned on, names from domain rules are resolved through the rule's exit: the address isn't spoofed on the way, and the CDN picks a node near the exit. A new option on the Server tab lets the handler see only connections to the addresses this DNS returned for those names; the rest of the traffic doesn't pass through it at all.

- **Rules read as "what → where".** A rule in the policy shows its lists on the left — `Domains work (20)`, an exit's own sites by their first domain `youtube.com +19`, `Russia, China +1`, `Office (12 networks)` — and the exit on the right. A rule's own name is shown small and grey above it, only when it adds something: the doubled "mobile — mobile" is gone. A rule that is off stays in its place, grey and struck through.

- **The status line says what the panel is doing.** Besides Running and Error: Starting…, Restarting the AWG server…, Switching the engine…, Updating… (also when the update was started in the server console) and No connection to the panel — the last one only after two missed checks, so a moment of bad mobile network doesn't paint it red.

- **Exact AWG version** on exit cards (`AWG 3.1`, `2.0`, `1.5`, `1.0`), without the internal interface name. The status dot sits level with its text everywhere.

- **QUIC through SOCKS5 is your choice.** A SOCKS5 exit has a new box, "Let QUIC (HTTP/3) through the proxy", off by default: browsers then open sites over HTTPS right away instead of first waiting for QUIC through a proxy that may not carry UDP. Tick it if your proxy passes UDP — **Check** on the exit now says whether it does.

- **Exit check tells the truth.** The latency of a SOCKS5 exit is measured to the first answer through the proxy (it used to show 0 ms), the external IP is found over HTTPS on port 443 too, and when it can't be found the message says why.

- **Domain rules can fail closed.** The domain handler is now watched every second and restarted at once. A new box on the Routing tab, "If domain rules don't work, block all traffic of their clients", blocks those clients while the handler is down (including while the panel restarts or updates), instead of letting listed sites go by the other rules. The header, the event log and Telegram tell you when that happens.

- **SOCKS5 exits start again on servers with recent Intel Xeon processors.** Since 1.20.0 the tunnel to a SOCKS5 proxy didn't start at all on Xeon with AMX (4th generation and newer, common at cloud providers): the exit showed "tunnel to the proxy did not start" without a reason. The cause is a stricter check of the signal stack in the system library the tunnel is built with; the build now gives it enough room.

- **Several server addresses for clients.** If your server has more than one public IP (or a few domains), list them in **Server → Additional server addresses**. Pick one for everyone in **Address in configs**, or give a client its own in its window or when you create it — so blocking one address doesn't cut off everyone. Only the address clients connect to changes: websites still see the server's main address or the exit's. A client gets the new address when it downloads its config again. Thanks to @MacSergey (#37).

- **A clear message when the kernel module refuses an exit.** Instead of a piece of a system command and the path to a temporary file the panel now says: the kernel module didn't accept this exit's config, amneziawg-go did, and exits run on amneziawg-go until the AWG server restarts. If the problem is in I1–I5 (the module reads them more strictly than amneziawg-go), the message says which field and what's wrong — for example, `I1: <b> needs 0x and an even number of hex digits`.

- **Configs with non-Latin client names import again.** The AmneziaWG and WireGuard apps refused a file named in Russian, Chinese or Persian (they accept only Latin letters, digits and `_=+.-`, up to 15). Such clients now get a file named with 8 digits — the same each time you download it.

- **Safer when the AWG server restarts.** After a restart of the AWG container, clients could go to the internet past the exits for up to 10 seconds. The panel now notices the restart at once. A server installed with this version into its own container, and a server on the host, put the panel's protective rules up even before they start. With "When the panel is stopped: Send everything direct" the panel doesn't do this. For a server on the host, the installer adds the small `nft` program if it is missing.

- **Security.** The server address that goes into client configs is now checked (a spoofed answer could add commands to every client's config). The panel's pages load scripts only from the panel itself. Slow connections can no longer take all of the panel's places, an attacker on IPv6 can't get around the limit by changing addresses, and the addresses you logged in from recently get in even during such an attack. Password guesses sent in parallel are counted too.

- **Telegram: commands only from a numeric Chat ID.** A `@name` can later be taken by someone else, so bot control now needs the chat's number. If your control was set to a `@name`, send the bot any command in your private chat with it — it replies with your chat's number (in a group it stays silent); put it in **System → Telegram notifications**. Notifications to a channel `@name` work as before.

- **More reliable.** When an exit goes down, its clients spread over the other exits instead of piling onto one. Country and network lists that can't be downloaded directly (GitHub is often closed in China and Iran) are downloaded through your working exits, and a broken download can no longer turn into "half the internet goes direct". If a list didn't download or is empty, the rule line says so. DNS on the server no longer gives IPv6 addresses that can't work through the tunnel, so apps don't wait for them. The route check finds a site's address the same way the client will. A SOCKS5 proxy with a silent DNS no longer stalls the panel, and configs and the client's page open at once. A client whose term you extend or whose limit you raise at that very moment is no longer turned off by the old values.

- **The Server tab asks before you leave it with unsaved changes**, and saving a list that has to be downloaded no longer makes you wait. The domain list window explains that Google and big CDNs may carry one site over another site's open connection, so it's best to keep all domains of one owner in one list.

- **Faster with many clients.** With a thousand clients the page no longer redraws the whole table every few seconds: when nothing changed only the header updates, and when something did only the changed rows are replaced — on a slow phone a check went from about 0.4 s to 0.05 s. The panel also starts far fewer helper commands on the server every 10 seconds (with 20 exits, about 8 instead of 66).

- **Mistakes in forms are easier to find.** When the panel refuses to save an exit, the Server tab or the Telegram settings, the field with the mistake gets a red frame and the cursor. A window you have open no longer changes under you while the panel refreshes in the background.

- **Smaller things.** The exit window shows the exit's interface (`awgrN`) next to its name; the description of DNS on the server says plainly how it works; the Telegram box for a busy server names the real limits (memory above 90%, CPU above 95%); a rule you name like its exit keeps that name (only the names the exit window wrote before 1.21.0 are removed, once).

- **Installer.** Any port from 1 to 65535 for AmneziaWG and the panel; random ports are four-digit (some mobile operators cut high ones) and a random AmneziaWG port avoids ports of other VPNs and VoIP. UDP 53 is left to DNS on the server; the panel doesn't take 80 or 443. With access through an ssh tunnel, the final command names the user you actually log in as (not always `root`) and adds `-p` when ssh is not on port 22.

- **Even fewer moments past the exits.** When the AWG server or the whole server restarts, the panel now sets the route of each exit before it marks clients' traffic for it, and a safety rule in the firewall refuses anything marked for an exit that would leave any other way. With a container made by the AmneziaVPN app traffic can still go direct for a few seconds after a reboot, until the panel starts: the README explains how to avoid it (move the server to the host).

- **Security.** A backup from someone else can no longer hide a command in the AmneziaWG server's config (the panel used to strip such commands, but there were two ways around it) — a backup like that is refused. A panel without a password no longer reads big requests into memory, another site's cookie on the same server no longer logs you out again and again, and the hint for Telegram control now says honestly that the bot can delete a client.

- **Domain lists and the domain handler, more reliable.** Lists of domains from links are downloaded once a day again (in 1.20.0 they were downloaded every 5 minutes). If one of the links fails, the list stays as it was and the panel shows the error, instead of silently losing that link's sites for a day; a download that breaks off halfway no longer replaces a list. A handful of rare cases where a listed site could go the wrong way are fixed: very long site names, a connection that starts but never finishes saying which site it is for, a site name ending with a dot, a rare kind of HTTP/3 packet. DNS on the server can no longer be made to "forget" a site for other clients, and its cache can't eat the server's memory.

- **Telegram.** If an exit goes down and up several times in a row, the last message in the chat now tells how it really is. The bot sends the config of a client with `<` in its name, stops obeying commands as soon as you turn control off, and no longer stops working after a broken answer from Telegram.

- **Interface fixes.** Error messages are no longer hidden under an open window; the new DNS filter box can be saved; buttons lower on the Server tab no longer silently drop changes made above; the page no longer stays empty when the panel didn't answer right after sign-in; a proxy entered as `address:port` is accepted; a second Enter no longer creates two clients; on a phone, client names are no longer squeezed when an exit is down. Texts are clearer in all four languages.

- **Lighter with many clients.** The page gets about a twentieth less data every few seconds and draws the client list faster on slow phones; the server no longer rewrites its traffic counters file every minute when nothing changed.

## Update

**System → Update** in the panel (since 1.4.0), or on the server:

    awg-router update

New install (Ubuntu or Debian, as root):

    curl -fsSL https://raw.githubusercontent.com/r-slashslash/AWG-Router/main/install.sh | bash

**Going back to 1.20.0.** 1.21.0 keeps the text of the lists you typed in yourself (networks and domains) in separate files instead of `state.json`. 1.20.0 started on these files shows such lists empty (their rules keep working with the list as it was last built); to get the texts back there, restore a backup (**System → Backup**): backups still carry the texts. A backup made in 1.21.0 loads in 1.20.0 only if it has none of the new domain rules (to an AmneziaWG exit, Direct or Block); a backup made before the update always does. To go back, run on the server: `AWGR_SRC_URL=https://github.com/r-slashslash/AWG-Router/releases/download/v1.20.0/awg-router.tar.gz awg-router update`. Don't press **Refresh now** on such a list in 1.20.0: it rebuilds the list from its empty text, and its rules lose their addresses (1.21.0 rebuilds such lists from their texts when you come back). 1.20.0 neither uses nor removes the file with the rules “before the panel” (`awgr-hold-awg0.nft` next to the server's config); if you stay on 1.20.0, you can delete it.

## Что изменилось

- **Правила по доменам на любой выход.** Список сайтов теперь можно направить через выход AmneziaWG, напрямую или в блок, а не только через прокси SOCKS5. Через SOCKS5 прокси по-прежнему получает имя сайта и сам находит адрес; через AmneziaWG и «напрямую» соединение идёт к адресу, который устройство получило из своего DNS, поэтому, если провайдер подменяет DNS, включите DNS на сервере. В окне выхода AmneziaWG теперь тоже можно задать сайты и списки. Правило по доменам, которое ничего не меняет (ведёт туда же, куда всё остальное), больше не пускает весь веб-трафик клиента через обработчик доменов.

- **HTTP/3 (QUIC) работает и с правилами по доменам.** Раньше у клиентов с правилами по доменам HTTP/3 отключался для всех сайтов. Теперь сервер узнаёт имя сайта и из первых пакетов QUIC: сайт из списка идёт через свой выход AmneziaWG или напрямую по HTTP/3, сайт за выходом SOCKS5 переводится на HTTPS (там прокси получает имя), если вы не разрешили этому прокси QUIC, а остальные сайты сохраняют HTTP/3. На серверах, где ядро не умеет очередь пакетов (часть OpenVZ/LXC), всё остаётся как раньше, и панель об этом пишет.

- **DNS на сервере следует правилам по доменам.** С включённым DNS на сервере имена из правил по доменам разбираются через выход правила: адрес не подменяется по дороге, а CDN выбирает узел рядом с выходом. Новая настройка на вкладке «Сервер» позволяет обработчику видеть только соединения к адресам, которые этот DNS вернул для таких имён; остальной трафик через него вообще не идёт.

- **Правила читаются как «что → куда».** Правило в политике показывает слева свои списки — `Домены work (20)`, свои сайты выхода по первому домену `youtube.com +19`, `Россия, Китай +1`, `Офис (12 сетей)`, — а справа выход. Своё название правила — мелкой серой строкой над ним и только когда оно что-то добавляет: двойного «mobile — mobile» больше нет. Выключенное правило остаётся на месте, серым и зачёркнутым.

- **Строка состояния говорит, что делает панель.** Кроме «Работает» и «Ошибка»: «Запуск…», «Перезапуск сервера AWG…», «Смена движка…», «Обновление…» (и когда обновление запущено в консоли сервера) и «Нет связи с панелью» — последнее только после двух пропущенных проверок, чтобы секундный сбой мобильной сети не красил шапку в красный.

- **Точная версия AWG** на карточках выходов (`AWG 3.1`, `2.0`, `1.5`, `1.0`), без внутреннего имени интерфейса. Точка состояния везде стоит ровно по центру строки.

- **QUIC через SOCKS5 — на ваш выбор.** У выхода SOCKS5 появилась галочка «Пропускать QUIC (HTTP/3) через прокси», по умолчанию выключена: тогда браузеры сразу открывают сайты по HTTPS, а не ждут сначала QUIC через прокси, который может не пропускать UDP. Включите её, если прокси пропускает UDP, — кнопка **Проверить** у выхода теперь это показывает.

- **Проверка выхода говорит правду.** Задержка выхода SOCKS5 меряется до первого ответа через прокси (раньше показывалось 0 мс), внешний IP ищется и по HTTPS на порту 443, а если его не найти — сообщение говорит почему.

- **Правила по доменам могут блокировать при сбое.** За обработчиком доменов панель теперь смотрит каждую секунду и сразу его перезапускает. Новая галочка на вкладке «Маршрутизация» — «Если правила по доменам не работают — блокировать весь трафик их клиентов» — блокирует таких клиентов, пока обработчик не работает (и пока панель перезапускается или обновляется), вместо того чтобы пускать сайты из списков по остальным правилам. Шапка, журнал и Telegram говорят, когда это происходит.

- **Выходы SOCKS5 снова запускаются на серверах с новыми процессорами Intel Xeon.** С 1.20.0 туннель к прокси SOCKS5 не запускался вовсе на Xeon с AMX (4-е поколение и новее, частые у облачных провайдеров): у выхода было «не запустился туннель к прокси» без причины. Причина — более строгая проверка стека сигналов в системной библиотеке, с которой собран туннель; теперь сборка даёт ему достаточно места.

- **Несколько адресов сервера для клиентов.** Если у сервера несколько внешних IP (или несколько доменов), впишите их в **Сервер → Дополнительные адреса сервера**. Один из них можно выбрать для всех в **Адресе в конфигах** или дать клиенту свой — в его окне или при создании, — чтобы блокировка одного адреса не отрезала всех. Меняется только адрес, к которому подключаются клиенты: сайты по-прежнему видят основной адрес сервера или адрес выхода. Новый адрес клиент получит, когда скачает конфиг заново. Спасибо @MacSergey (#37).

- **Понятное сообщение, когда модуль ядра не принял выход.** Вместо куска системной команды и пути к временному файлу панель теперь пишет: модуль ядра не принял конфиг этого выхода, amneziawg-go принял, и выходы работают на amneziawg-go до перезапуска сервера AWG. Если дело в I1–I5 (модуль читает их строже amneziawg-go), сообщение называет поле и что в нём не так — например, `I1: в <b> нужно 0x и чётное число шестнадцатеричных цифр`.

- **Конфиги клиентов с русскими именами снова импортируются.** Приложения AmneziaWG и WireGuard не принимали файл с именем на русском, китайском или персидском (они принимают только латиницу, цифры и `_=+.-`, до 15 знаков). Теперь такой клиент получает файл из 8 цифр — при каждом скачивании одних и тех же.

- **Безопаснее при перезапуске сервера AWG.** После перезапуска контейнера AWG клиенты до 10 секунд могли ходить в интернет мимо выходов. Теперь панель замечает перезапуск сразу. Сервер, установленный этой версией в свой контейнер, и сервер на хосте ставят защитные правила панели ещё до своего запуска. С настройкой «Когда панель останавливают: Вернуть всё напрямую» панель этого не делает. Для сервера на хосте установщик при необходимости ставит небольшую программу `nft`.

- **Безопасность.** Адрес сервера, который попадает в конфиги клиентов, теперь проверяется (подменённый ответ мог дописать команды в конфиг каждого клиента). Страницы панели берут скрипты только у самой панели. «Медленные» соединения больше не могут занять все места панели, атакующий с IPv6 не обойдёт предел сменой адреса, а с адресов, откуда вы недавно входили, вы попадёте в панель даже во время такой атаки. Параллельные попытки подобрать пароль тоже считаются.

- **Telegram: команды — только из чата с числовым Chat ID.** @имя потом может занять другой человек, поэтому для управления ботом теперь нужен номер чата. Если управление было настроено на @имя, напишите боту любую команду в личном чате с ним — он ответит номером вашего чата (в группе бот молчит); впишите его в **«Система» → «Уведомления в Telegram»**. Уведомления в канал по @имени работают как раньше.

- **Надёжнее.** Когда выход падает, его клиенты расходятся по остальным выходам, а не наваливаются на один. Списки стран и сетей, которые не скачиваются напрямую (в Китае и Иране GitHub часто закрыт), скачиваются через ваши рабочие выходы, а оборванное скачивание больше не может превратиться в «половину интернета напрямую». Если список не скачался или пуст, это видно прямо в строке правила. DNS на сервере больше не отдаёт адреса IPv6, которые через туннель всё равно не работают, — приложения их не ждут. «Проверка маршрута» узнаёт адрес сайта так же, как его узнает клиент. Прокси SOCKS5 с молчащим DNS больше не подвешивает панель, а конфиги и личная страница клиента открываются сразу. Клиент, которому вы продлили срок или подняли лимит в ту же секунду, больше не отключается по старым значениям.

- **Вкладка «Сервер» спрашивает, прежде чем уйти с несохранёнными правками**, а сохранение списка, который нужно скачать, больше не заставляет ждать. В окне списка доменов объяснено, что Google и крупные CDN могут везти один сайт по уже открытому соединению другого, поэтому все домены одного владельца лучше держать в одном списке.

- **Быстрее при большом числе клиентов.** С тысячей клиентов страница больше не перерисовывает всю таблицу каждые несколько секунд: если ничего не изменилось, обновляется только шапка, а если изменилось — только нужные строки. На медленном телефоне проверка ускорилась примерно с 0,4 с до 0,05 с. Ещё панель запускает на сервере гораздо меньше служебных команд каждые 10 секунд (при 20 выходах — около 8 вместо 66).

- **Ошибку в форме легче найти.** Если панель не сохраняет выход, вкладку «Сервер» или настройки Telegram, поле с ошибкой выделяется красной рамкой, и в него встаёт курсор. Открытое окно больше не меняется само, пока панель обновляет данные в фоне.

- **Мелочи.** В окне выхода рядом с именем виден его интерфейс (`awgrN`); описание DNS на сервере просто объясняет, как он работает; галочка Telegram о загрузке сервера называет настоящие пороги (память больше 90%, процессор больше 95%); правило, которое вы назвали как его выход, сохраняет это имя (подписи, которые окно выхода ставило до 1.21.0, убираются один раз).

- **Установщик.** Любой порт от 1 до 65535 для AmneziaWG и панели; случайные порты — четырёхзначные (некоторые мобильные операторы режут высокие), и случайный порт AmneziaWG обходит порты других VPN и VoIP. UDP 53 оставлен DNS на сервере; панель не встаёт на 80 и 443. При доступе через ssh-туннель итоговая команда называет пользователя, под которым вы на самом деле входите (а не всегда `root`), и добавляет `-p`, если ssh не на порту 22.

- **Ещё меньше моментов мимо выходов.** Когда перезапускается сервер AWG или весь сервер, панель теперь сначала ставит маршрут каждого выхода, а потом отправляет в него трафик клиентов, а страховочное правило отклоняет всё, что помечено для выхода, но уходит другим путём. С контейнером приложения AmneziaVPN после перезагрузки трафик ещё может несколько секунд идти напрямую, пока не запустится панель: в README написано, как этого избежать (перенести сервер на хост).

- **Безопасность.** Чужая резервная копия больше не может спрятать команду в конфиге сервера AmneziaWG (панель и раньше вырезала такие команды, но защиту можно было обойти двумя способами) — такая копия не загрузится. Панель без пароля больше не читает большие запросы в память, чужая cookie на том же сервере больше не выбрасывает вас из панели по кругу, а подсказка про управление из Telegram честно говорит, что бот может удалить клиента.

- **Списки доменов и их обработчик — надёжнее.** Списки доменов по ссылкам снова скачиваются раз в сутки (в 1.20.0 они скачивались каждые 5 минут). Если одна из ссылок не скачалась, список остаётся прежним, а панель показывает ошибку, — раньше сайты этой ссылки молча пропадали на сутки; оборванная на середине загрузка больше не заменяет список. Исправлены редкие случаи, когда сайт из списка мог уйти не туда: очень длинные имена сайтов, соединение, которое начало, но так и не сказало, к какому сайту идёт, имя сайта с точкой на конце, редкий вид пакетов HTTP/3. DNS на сервере больше нельзя заставить «забыть» сайт для других клиентов, а его кэш не съест память сервера.

- **Telegram.** Если выход несколько раз подряд ложится и поднимается, последнее сообщение в чате теперь говорит, как на самом деле. Бот присылает конфиг клиента со знаком `<` в имени, перестаёт выполнять команды сразу после выключения управления и больше не замолкает после оборванного ответа Telegram.

- **Исправления в интерфейсе.** Ошибки больше не прячутся под открытым окном; новую галочку фильтра DNS можно сохранить; кнопки ниже на вкладке «Сервер» больше не выбрасывают молча правки выше; страница больше не остаётся пустой, если панель не ответила сразу после входа; прокси в виде `адрес:порт` принимается; второй Enter не создаёт двух клиентов; на телефоне имена клиентов не сжимаются, когда какой-то выход лежит. Тексты понятнее на всех четырёх языках.

- **Легче с большим числом клиентов.** Страница каждые несколько секунд получает примерно на двадцатую часть меньше данных и быстрее рисует список клиентов на слабых телефонах; сервер больше не переписывает файл счётчиков трафика каждую минуту, когда ничего не изменилось.

**«Система» → «Обновить»** в панели (начиная с 1.4.0) или на сервере:

Новая установка (Ubuntu или Debian, от root):

Версия 1.20.0 на этих файлах покажет такие списки пустыми (их правила работают по последней собранной версии списка); чтобы тексты вернулись, загрузите резервную копию (**«Система» → «Резервная копия»**): копии по-прежнему содержат тексты. ## 改动

- **域名规则可指向任意出口。** 网站列表现在可以经 AmneziaWG 出口、直连或阻止，而不仅仅是经 SOCKS5 代理。经 SOCKS5 时代理仍然拿到网站名称并自己解析地址；经 AmneziaWG 和直连时，连接发往设备从自己的 DNS 得到的地址，因此如果运营商篡改 DNS，请开启服务器上的 DNS。AmneziaWG 出口的窗口现在也可以设置网站和列表。不起作用的域名规则（与其余流量去向相同）不再让客户端的全部网页流量经过域名处理程序。

- **有域名规则时 HTTP/3（QUIC）依然可用。** 以前，有域名规则的客户端对所有网站都失去 HTTP/3。现在服务器也能从 QUIC 的最初几个数据包中识别网站名称：列表中的网站经自己的 AmneziaWG 出口或直连走 HTTP/3，SOCKS5 出口后的网站改用 HTTPS（代理在那里拿到名称），除非你允许该代理传输 QUIC，其他网站保留 HTTP/3。在内核不支持数据包队列的服务器上（部分 OpenVZ/LXC），一切照旧，面板会说明。

- **服务器上的 DNS 遵循域名规则。** 开启服务器上的 DNS 后，域名规则中的名称经规则的出口解析：地址在途中不会被篡改，CDN 会选择靠近出口的节点。「服务器」标签页上的新选项可让处理程序只看到发往此 DNS 为这些名称返回的地址的连接；其余流量完全不经过它。

- **规则按「匹配什么 → 去哪里」显示。** 策略中的规则左边显示它的列表——`域名 work (20)`、出口自己的网站按第一个域名显示 `youtube.com +19`、`俄罗斯、中国 +1`、`办公室 (12 个网络)`——右边是出口。规则自己的名称只在有意义时以灰色小字显示在上方：不再出现重复的「mobile — mobile」。已关闭的规则留在原位，显示为灰色并带删除线。

- **状态栏显示面板正在做什么。** 除了「运行中」和「错误」之外，还有：正在启动…、正在重启 AWG 服务器…、正在切换引擎…、正在更新…（包括从服务器控制台启动的更新）以及「无法连接面板」——后者只在连续两次检查失败后才出现，移动网络的短暂波动不会让它变红。

- 出口卡片显示**准确的 AWG 版本**（`AWG 3.1`、`2.0`、`1.5`、`1.0`），不再显示内部接口名。状态圆点在各处都与文字居中对齐。

- **是否让 QUIC 经由 SOCKS5 由你决定。** SOCKS5 出口新增「允许 QUIC（HTTP/3）经由代理」选项，默认关闭：这样浏览器会直接用 HTTPS 打开网站，而不是先白等经由可能不支持 UDP 的代理的 QUIC。如果你的代理支持 UDP，就勾选它——出口的 **检查** 按钮现在会显示是否支持。

- **出口检查结果更真实。** SOCKS5 出口的延迟按经由代理收到的第一个应答计算（以前显示 0 毫秒），外部 IP 也会通过 443 端口的 HTTPS 查询，查不到时会说明原因。

- **域名规则失效时可以阻断。** 面板现在每秒检查一次域名处理程序，并立即重启它。「路由」选项卡新增「域名规则不工作时，阻止其客户端的全部流量」：处理程序不工作期间（包括面板重启或更新时）阻止这类客户端，而不是让列表中的网站按其他规则走。顶栏、日志和 Telegram 会告诉你何时发生。

- **在较新的 Intel Xeon 处理器服务器上，SOCKS5 出口重新可以启动。** 自 1.20.0 起，在带 AMX 的 Xeon（第 4 代及更新，云服务商中很常见）上，通往 SOCKS5 代理的隧道完全无法启动：出口只显示「到代理的隧道未能启动」，没有原因。原因是构建隧道所用的系统库对信号栈的检查更严格了；现在构建时为它留出了足够的空间。

- **为客户端提供多个服务器地址。** 如果服务器有多个公网 IP（或多个域名），请把它们填入 **服务器 → 服务器的附加地址**。可以在 **配置中的地址** 里为所有客户端选择其中一个，也可以在客户端窗口中或创建客户端时为它单独指定——这样封锁一个地址不会让所有人断线。改变的只是客户端连接的地址：网站看到的仍是服务器的主地址或出口的地址。客户端重新下载配置后才会拿到新地址。感谢 @MacSergey（#37）。

- **内核模块不接受出口时，提示清楚了。** 面板不再显示一段系统命令和临时文件的路径，而是说明：内核模块不接受该出口的配置，amneziawg-go 接受了，在 AWG 服务器重启之前出口改用 amneziawg-go 运行。如果问题出在 I1–I5（模块的解析比 amneziawg-go 更严格），提示会指出是哪个字段、哪里不对。

- **非拉丁字母命名的客户端配置可以再次导入。** AmneziaWG 和 WireGuard 应用拒绝以俄文、中文或波斯文命名的文件（它们只接受拉丁字母、数字和 `_=+.-`，最多 15 个字符）。现在这类客户端的文件名为 8 位数字，每次下载都相同。

- **AWG 服务器重启时更安全。** 以前 AWG 容器重启后，客户端最多有 10 秒会绕过出口直接上网。现在面板会立即发现重启。用此版本安装在自己容器中的服务器以及主机上的服务器，会在启动之前就设置好面板的保护规则。如果设置了「面板停止时：全部改为直连」，面板不会这样做。对于主机上的服务器，如果缺少小程序 `nft`，安装程序会自动安装。

- **安全。** 写入客户端配置的服务器地址现在会经过检查（被篡改的应答可能会往每个客户端的配置里添加命令）。面板页面只从面板本身加载脚本。「慢速」连接不再能占满面板的所有连接位置，IPv6 攻击者无法通过更换地址绕过限制，而你最近登录过的地址即使在这种攻击期间也能进入面板。并行的密码猜测也会被计数。

- **Telegram：只接受来自数字 Chat ID 的命令。** @名称以后可能被别人占用，所以控制机器人现在需要聊天的号码。如果控制设置的是 @名称，请在与机器人的私聊中给它发送任意命令——它会回复你的聊天号码（在群组中它不回复）；把它填入 **系统 → Telegram 通知**。发往频道 @名称 的通知照常工作。

- **更可靠。** 某个出口断开时，它的客户端会分散到其他出口，而不是全部挤到一个出口上。无法直接下载的国家和网络列表（在中国和伊朗 GitHub 常被封锁）会通过你正在工作的出口下载，中断的下载也不会再变成「一半互联网直连」。如果列表未能下载或为空，规则行中会直接显示。服务器上的 DNS 不再返回经隧道无法使用的 IPv6 地址，应用不会再白等。「路由检查」用与客户端相同的方式获取网站地址。DNS 无响应的 SOCKS5 代理不再让面板卡住，配置和客户端个人页面会立即打开。在同一时刻为客户端延长期限或提高限额，客户端不会再按旧值被关闭。

- **「服务器」标签页在有未保存的修改时会先询问再离开**，保存需要下载的列表也不必再等待。域名列表窗口说明了 Google 和大型 CDN 可能通过另一网站已打开的连接传输某个网站，因此最好把同一所有者的所有域名放在同一个列表中。

- **客户端很多时更快。** 有一千个客户端时，页面不再每隔几秒重绘整张表格：没有变化时只更新顶栏，有变化时只替换变化的行。在较慢的手机上，一次检查从约 0.4 秒缩短到约 0.05 秒。面板每 10 秒在服务器上启动的辅助命令也少得多（20 个出口时约 8 条，而不是 66 条）。

- **表单中的错误更容易找到。** 面板拒绝保存出口、「服务器」标签页或 Telegram 设置时，出错的字段会显示红框，光标会移到该字段。面板在后台刷新数据时，已打开的窗口不再自行变化。

- **小改动。** 出口窗口在名称旁显示其接口（`awgrN`）；服务器上的 DNS 的说明直接讲清它如何工作；Telegram 中关于服务器负载的选项写明真实阈值（内存超过 90%、CPU 超过 95%）；你按出口名称命名的规则会保留这个名称（只会一次性去掉 1.21.0 之前出口窗口自动写上的名称）。

- **安装程序。** AmneziaWG 和面板可使用 1 到 65535 的任意端口；随机端口为四位数（部分移动运营商会屏蔽高端口），AmneziaWG 的随机端口会避开其他 VPN 和 VoIP 的端口。UDP 53 留给服务器上的 DNS；面板不会使用 80 和 443。通过 ssh 隧道访问时，最后显示的命令会使用你实际登录的用户（而不总是 `root`），ssh 不在 22 端口时还会加上 `-p`。

- **绕过出口的情况进一步减少。** AWG 服务器或整台服务器重启时，面板现在先为每个出口设好路由，再把客户端流量导向它；一条保护规则会拒绝所有标记给出口、却要从其他路径离开的流量。若使用 AmneziaVPN 应用创建的容器，重启后在面板启动前的几秒钟内流量仍可能直连：README 说明了如何避免（把服务器迁移到主机上）。

- **安全。** 别人给的备份不能再在 AmneziaWG 服务器配置里藏命令（面板以前就会删掉这类命令，但有两种绕过方法）——这样的备份会被拒绝。未登录时面板不再把大请求读进内存；同一服务器上其他网站的 cookie 不再让你反复被登出；Telegram 控制的提示现在如实说明机器人可以删除客户端。

- **域名列表及其处理程序更可靠。** 来自链接的域名列表恢复为每天下载一次（在 1.20.0 中每 5 分钟下载一次）。如果某个链接下载失败，列表保持原样，面板显示错误——以前该链接的网站会悄悄消失一天；中途中断的下载不再替换列表。修复了列表中的网站可能走错路的几种罕见情况：超长的网站名称、开始了却始终没说明去往哪个网站的连接、以点结尾的网站名称、一种罕见的 HTTP/3 数据包。服务器上的 DNS 不再会被人为地让其他客户端「忘记」某个网站，其缓存也不会耗尽服务器内存。

- **Telegram。** 如果某个出口连续多次中断又恢复，聊天中的最后一条消息现在反映真实状态。机器人能发送名称中带 `<` 的客户端配置，关闭控制后立即停止执行命令，并且不会在 Telegram 返回中断的响应后停止工作。

- **界面修复。** 错误提示不再藏在打开的窗口下面；新的 DNS 过滤复选框可以保存；「服务器」页下方的按钮不再悄悄丢弃上方的修改；登录后面板没有立即响应时页面不再一直空白；以 `地址:端口` 形式输入的代理可以被接受；第二次按 Enter 不再创建两个客户端；在手机上，某个出口中断时客户端名称不再被挤压。四种语言的文字都更清楚了。

- **客户端多时更轻快。** 页面每隔几秒收到的数据少了约二十分之一，在较慢的手机上绘制客户端列表更快；没有变化时，服务器不再每分钟重写流量计数文件。

## تغییرها

- **قانون‌های دامنه برای هر خروجی.** فهرست سایت‌ها اکنون می‌تواند از خروجی AmneziaWG، مستقیم یا به «مسدود» برود، نه فقط از پراکسی SOCKS5. از راه SOCKS5 پراکسی همچنان نام سایت را می‌گیرد و خودش نشانی را پیدا می‌کند؛ از راه AmneziaWG و مستقیم، اتصال به نشانی‌ای می‌رود که دستگاه از DNS خودش گرفته است، پس اگر ارائه‌دهنده DNS را دستکاری می‌کند، DNS روی سرور را روشن کنید. در پنجرهٔ خروجی AmneziaWG هم اکنون می‌توان سایت‌ها و فهرست‌ها را تنظیم کرد. قانون دامنه‌ای که چیزی را تغییر نمی‌دهد (به همان جایی می‌رود که بقیهٔ ترافیک) دیگر همهٔ ترافیک وب کلاینت را از پردازشگر دامنه‌ها عبور نمی‌دهد.

- **HTTP/3 (QUIC) با قانون‌های دامنه هم کار می‌کند.** پیش‌تر کلاینت‌هایی که قانون دامنه داشتند HTTP/3 را برای همهٔ سایت‌ها از دست می‌دادند. اکنون سرور نام سایت را از نخستین بسته‌های QUIC هم تشخیص می‌دهد: سایت فهرست از خروجی AmneziaWG خودش یا مستقیم با HTTP/3 می‌رود، سایتی که پشت خروجی SOCKS5 است به HTTPS برده می‌شود (آنجا پراکسی نام را می‌گیرد)، مگر این‌که QUIC را برای آن پراکسی روشن کرده باشید و بقیهٔ سایت‌ها HTTP/3 را نگه می‌دارند. روی سرورهایی که هسته‌شان صف بسته‌ها را پشتیبانی نمی‌کند (بخشی از OpenVZ/LXC) همه‌چیز مثل قبل می‌ماند و پنل این را می‌گوید.

- **DNS روی سرور از قانون‌های دامنه پیروی می‌کند.** با روشن بودن DNS روی سرور، نام‌های قانون‌های دامنه از راه خروجی قانون پیدا می‌شوند: نشانی در راه جعل نمی‌شود و CDN گرهی نزدیک خروجی را انتخاب می‌کند. یک گزینهٔ تازه در برگهٔ «سرور» باعث می‌شود پردازشگر فقط اتصال‌هایی را ببیند که به نشانی‌های برگردانده‌شده از این DNS برای این نام‌ها می‌روند؛ بقیهٔ ترافیک اصلاً از آن نمی‌گذرد.

- **قانون‌ها به شکل «چه چیزی ← به کجا» خوانده می‌شوند.** هر قانون در سیاست، فهرست‌هایش را در یک سو نشان می‌دهد — <bdi>`دامنه‌ها work (20)`</bdi>، سایت‌های خود خروجی با نخستین دامنه <bdi>`youtube.com +19`</bdi>، «روسیه، چین +۱»، «دفتر (۱۲ شبکه)» — و خروجی را در سوی دیگر. نام خود قانون فقط وقتی چیزی اضافه می‌کند با خط کوچک خاکستری بالای آن می‌آید: تکرار «mobile — mobile» دیگر نیست. قانون خاموش سر جایش می‌ماند، خاکستری و خط‌خورده.

- **نوار وضعیت می‌گوید پنل چه می‌کند.** افزون بر «در حال کار» و «خطا»: در حال راه‌اندازی…، در حال راه‌اندازی دوبارهٔ سرور AWG…، در حال تغییر موتور…، در حال به‌روزرسانی… (حتی وقتی به‌روزرسانی از کنسول سرور آغاز شده) و «اتصال به پنل برقرار نیست» — این آخری فقط پس از دو بررسی ناموفق پشت سر هم، تا یک لحظه اختلال شبکهٔ همراه آن را قرمز نکند.

- **نسخهٔ دقیق AWG** روی کارت خروجی‌ها (<bdi>`AWG 3.1`</bdi>، <bdi>`2.0`</bdi>، <bdi>`1.5`</bdi>، <bdi>`1.0`</bdi>)، بدون نام داخلی رابط. نقطهٔ وضعیت همه‌جا هم‌تراز با متن خودش است.

- **QUIC از راه SOCKS5 به انتخاب شما.** خروجی SOCKS5 گزینهٔ تازه‌ای دارد، «عبور QUIC (HTTP/3) از پراکسی»، که به‌طور پیش‌فرض خاموش است: در این حالت مرورگرها سایت‌ها را بی‌درنگ با HTTPS باز می‌کنند، نه این‌که نخست بیهوده منتظر QUIC از راه پراکسی‌ای بمانند که شاید UDP را عبور ندهد. اگر پراکسی شما UDP را عبور می‌دهد روشنش کنید — دکمهٔ **بررسی** خروجی اکنون این را نشان می‌دهد.

- **بررسی خروجی درست می‌گوید.** تأخیر خروجی SOCKS5 تا نخستین پاسخ از راه پراکسی سنجیده می‌شود (پیش‌تر 0 میلی‌ثانیه نشان داده می‌شد)، IP خارجی با HTTPS روی درگاه 443 هم جست‌وجو می‌شود و اگر پیدا نشود، پیام علتش را می‌گوید.

- **قانون‌های دامنه هنگام خرابی می‌توانند مسدود کنند.** پنل اکنون هر ثانیه پردازشگر دامنه را بررسی می‌کند و بی‌درنگ دوباره راهش می‌اندازد. گزینهٔ تازه در زبانهٔ «مسیریابی» — «اگر قانون‌های دامنه کار نکنند، همهٔ ترافیک کلاینت‌هایشان مسدود شود» — تا وقتی پردازشگر کار نمی‌کند (از جمله هنگام راه‌اندازی دوباره یا به‌روزرسانی پنل) این کلاینت‌ها را مسدود می‌کند، به‌جای این‌که سایت‌های فهرست طبق قانون‌های دیگر بروند. نوار بالا، گزارش رویدادها و Telegram می‌گویند کی این اتفاق می‌افتد.

- **خروجی‌های SOCKS5 روی سرورهایی با پردازنده‌های جدید Intel Xeon دوباره راه می‌افتند.** از 1.20.0 تونل به پراکسی SOCKS5 روی Xeonهای دارای AMX (نسل چهارم و جدیدتر، رایج نزد ارائه‌دهندگان ابری) اصلاً راه نمی‌افتاد: خروجی بدون دلیل نشان می‌داد «تونل به پراکسی راه‌اندازی نشد». علت، بررسی سخت‌گیرانه‌تر پشتهٔ سیگنال در کتابخانهٔ سیستمی است که تونل با آن ساخته می‌شود؛ اکنون ساخت جای کافی به آن می‌دهد.

- **چند آدرس سرور برای کلاینت‌ها.** اگر سرور چند IP عمومی (یا چند دامنه) دارد، آن‌ها را در **سرور ← آدرس‌های اضافهٔ سرور** بنویسید. یکی را می‌توانید در **آدرس در پیکربندی‌ها** برای همه انتخاب کنید یا به یک کلاینت آدرس خودش را بدهید — در پنجرهٔ آن یا هنگام ساختنش — تا مسدود شدن یک آدرس همه را قطع نکند. فقط آدرسی که کلاینت‌ها به آن وصل می‌شوند عوض می‌شود: سایت‌ها همچنان آدرس اصلی سرور یا آدرس خروجی را می‌بینند. کلاینت آدرس تازه را وقتی می‌گیرد که پیکربندی را دوباره دانلود کند. سپاس از <bdi>@MacSergey</bdi> (<bdi>#37</bdi>).

- **پیام روشن وقتی ماژول هسته خروجی را نمی‌پذیرد.** پنل به‌جای تکه‌ای از دستور سیستمی و مسیر یک فایل موقت اکنون می‌نویسد: ماژول هسته پیکربندی این خروجی را نپذیرفت، amneziawg-go پذیرفت، و تا راه‌اندازی دوبارهٔ سرور AWG خروجی‌ها با amneziawg-go کار می‌کنند. اگر مشکل در I1–I5 باشد (ماژول آن‌ها را سخت‌گیرانه‌تر از amneziawg-go می‌خواند)، پیام می‌گوید کدام فیلد و چه چیزی در آن نادرست است.

- **پیکربندی کلاینت‌هایی با نام غیرلاتین دوباره وارد می‌شود.** برنامه‌های AmneziaWG و WireGuard فایلی را که نامش روسی، چینی یا فارسی بود نمی‌پذیرفتند (فقط حروف لاتین، رقم و <bdi>`_=+.-`</bdi> تا 15 نویسه را می‌پذیرند). اکنون فایل چنین کلاینتی نامی از 8 رقم دارد — در هر بار دریافت همان.

- **امن‌تر هنگام راه‌اندازی دوبارهٔ سرور AWG.** پیش‌تر پس از راه‌اندازی دوبارهٔ کانتینر AWG، کلاینت‌ها تا ۱۰ ثانیه می‌توانستند بدون گذر از خروجی‌ها به اینترنت بروند. اکنون پنل راه‌اندازی دوباره را بی‌درنگ می‌بیند. سروری که با این نسخه در کانتینر خودش نصب شده و سرور روی میزبان، قانون‌های محافظ پنل را حتی پیش از راه‌اندازی خودشان برقرار می‌کنند. با گزینهٔ «هنگام توقف پنل: همه مستقیم شوند» پنل این کار را نمی‌کند. برای سرور روی میزبان، نصب‌کننده در صورت نیاز برنامهٔ کوچک <bdi>`nft`</bdi> را نصب می‌کند.

- **امنیت.** نشانی سرور که در پیکربندی کلاینت‌ها می‌رود اکنون بررسی می‌شود (پاسخ جعلی می‌توانست به پیکربندی هر کلاینت فرمان اضافه کند). صفحه‌های پنل اسکریپت را فقط از خود پنل بار می‌کنند. اتصال‌های «کُند» دیگر نمی‌توانند همهٔ جاهای پنل را بگیرند، مهاجم IPv6 با عوض کردن نشانی از محدودیت نمی‌گذرد، و از نشانی‌هایی که اخیراً با آن‌ها وارد شده‌اید حتی هنگام چنین حمله‌ای وارد پنل می‌شوید. تلاش‌های هم‌زمان برای حدس گذرواژه هم شمرده می‌شوند.

- **Telegram: فرمان فقط از چتی با Chat ID عددی.** ‎@نام را بعداً ممکن است کس دیگری بگیرد، برای همین فرمان دادن به ربات اکنون شمارهٔ چت را لازم دارد. اگر کنترل روی ‎@نام تنظیم شده بود، در چت خصوصی با ربات هر فرمانی بفرستید — شمارهٔ چت شما را پاسخ می‌دهد (در گروه پاسخی نمی‌دهد)؛ آن را در **سیستم ← اعلان‌های Telegram** بنویسید. اعلان‌ها به کانال با ‎@نام مثل قبل کار می‌کنند.

- **پایدارتر.** وقتی خروجی‌ای از کار می‌افتد، کلاینت‌هایش میان خروجی‌های دیگر پخش می‌شوند، نه این‌که همه روی یکی بریزند. فهرست‌های کشورها و شبکه‌ها که مستقیم دانلود نمی‌شوند (در چین و ایران GitHub اغلب بسته است) از راه خروجی‌های فعال شما دانلود می‌شوند، و دانلود نیمه‌کاره دیگر نمی‌تواند به «نیمی از اینترنت مستقیم» تبدیل شود. اگر فهرستی دانلود نشده یا خالی باشد، در همان سطر قانون دیده می‌شود. DNS روی سرور دیگر نشانی IPv6 که از تونل کار نمی‌کند نمی‌دهد، پس برنامه‌ها منتظرش نمی‌مانند. «بررسی مسیر» نشانی سایت را همان‌طور پیدا می‌کند که کلاینت پیدا خواهد کرد. پراکسی SOCKS5 با DNS خاموش دیگر پنل را معطل نمی‌کند و پیکربندی و صفحهٔ شخصی کلاینت بی‌درنگ باز می‌شوند. کلاینتی که درست در همان لحظه مدتش را تمدید یا محدودیتش را بالا برده‌اید، دیگر با مقدارهای قدیمی خاموش نمی‌شود.

- **برگهٔ «سرور» پیش از ترک با تغییرهای ذخیره‌نشده می‌پرسد**، و ذخیرهٔ فهرستی که باید دانلود شود دیگر منتظر نمی‌گذارد. پنجرهٔ فهرست دامنه توضیح می‌دهد که Google و CDNهای بزرگ ممکن است یک سایت را از راه اتصال باز سایت دیگری ببرند، پس بهتر است همهٔ دامنه‌های یک مالک در یک فهرست باشند.

- **با کلاینت‌های زیاد سریع‌تر.** با هزار کلاینت، صفحه دیگر هر چند ثانیه کل جدول را از نو نمی‌کشد: اگر چیزی تغییر نکرده باشد فقط نوار بالا به‌روز می‌شود و اگر تغییر کرده باشد فقط ردیف‌های لازم عوض می‌شوند. روی یک گوشی کند، هر بررسی از حدود ۰٫۴ ثانیه به حدود ۰٫۰۵ ثانیه رسید. پنل هر ۱۰ ثانیه هم فرمان‌های کمکی بسیار کمتری روی سرور اجرا می‌کند (با ۲۰ خروجی، حدود ۸ به‌جای ۶۶).

- **خطای فرم راحت‌تر پیدا می‌شود.** اگر پنل خروجی، برگهٔ «سرور» یا تنظیمات Telegram را ذخیره نکند، فیلدی که خطا دارد قاب قرمز می‌گیرد و نشانگر در آن قرار می‌گیرد. پنجرهٔ باز دیگر هنگام به‌روزرسانی پس‌زمینهٔ پنل خودبه‌خود تغییر نمی‌کند.

- **ریزه‌کاری‌ها.** پنجرهٔ خروجی کنار نامش رابط آن (<bdi>`awgrN`</bdi>) را نشان می‌دهد؛ توضیح DNS روی سرور ساده می‌گوید چگونه کار می‌کند؛ گزینهٔ تلگرام دربارهٔ بار سرور آستانه‌های واقعی را می‌گوید (حافظه بیش از ۹۰٪، پردازنده بیش از ۹۵٪)؛ قانونی که هم‌نام خروجی‌اش گذاشته‌اید این نام را نگه می‌دارد (فقط نام‌هایی که پنجرهٔ خروجی پیش از 1.21.0 می‌نوشت، یک بار پاک می‌شوند).

- **نصب‌کننده.** هر درگاهی از 1 تا 65535 برای AmneziaWG و پنل؛ درگاه‌های تصادفی چهاررقمی‌اند (برخی اپراتورهای همراه درگاه‌های بالا را می‌بندند) و درگاه تصادفی AmneziaWG از درگاه‌های VPNها و VoIP دیگر دوری می‌کند. <bdi>UDP 53</bdi> برای DNS روی سرور می‌ماند؛ پنل روی 80 و 443 قرار نمی‌گیرد. با دسترسی از راه تونل ssh، فرمان پایانی نام کاربری‌ای را می‌آورد که واقعاً با آن وارد می‌شوید (نه همیشه <bdi>`root`</bdi>) و اگر ssh روی درگاه 22 نباشد، <bdi>`-p`</bdi> را اضافه می‌کند.

- **باز هم کمتر ترافیک از کنار خروجی‌ها.** وقتی سرور AWG یا کل سرور دوباره راه‌اندازی می‌شود، پنل اکنون اول مسیر هر خروجی را می‌سازد و بعد ترافیک کلاینت‌ها را به آن می‌فرستد، و یک قانون محافظ هر چیزی را که برای خروجی علامت خورده ولی از راه دیگری بیرون می‌رود رد می‌کند. با کانتینری که برنامهٔ AmneziaVPN ساخته است، پس از راه‌اندازی دوباره هنوز ممکن است چند ثانیه، تا پنل اجرا شود، ترافیک مستقیم برود: README توضیح می‌دهد چطور از آن پرهیز کنید (انتقال سرور به میزبان).

- **امنیت.** پشتیبانِ دیگران دیگر نمی‌تواند فرمانی را در پیکربندی سرور AmneziaWG پنهان کند (پنل پیش از این هم چنین فرمان‌هایی را حذف می‌کرد، اما دو راه دور زدن داشت) — چنین پشتیبانی پذیرفته نمی‌شود. پنل بدون رمز دیگر درخواست‌های بزرگ را در حافظه نمی‌خواند، کوکی سایت دیگری روی همان سرور دیگر شما را پشت سر هم از پنل بیرون نمی‌اندازد، و راهنمای کنترل از تلگرام اکنون صادقانه می‌گوید که ربات می‌تواند کلاینت را حذف کند.

- **فهرست‌های دامنه و پردازشگر آن‌ها، قابل‌اعتمادتر.** فهرست‌های دامنه از پیوندها دوباره روزی یک بار دانلود می‌شوند (در 1.20.0 هر ۵ دقیقه دانلود می‌شدند). اگر یکی از پیوندها دانلود نشود، فهرست همان قبلی می‌ماند و پنل خطا را نشان می‌دهد؛ پیش از این سایت‌های آن پیوند بی‌صدا یک روز ناپدید می‌شدند. دانلودی که نیمه‌کاره قطع شود دیگر جای فهرست را نمی‌گیرد. چند حالت نادر که در آن‌ها سایتی از فهرست ممکن بود راه اشتباه برود رفع شد: نام‌های بسیار بلند سایت، اتصالی که شروع می‌شود ولی هرگز نمی‌گوید به کدام سایت می‌رود، نام سایت با نقطه در پایان، و نوعی نادر از بسته‌های HTTP/3. دیگر نمی‌توان DNS روی سرور را وادار کرد سایتی را برای کلاینت‌های دیگر «فراموش» کند، و کش آن حافظهٔ سرور را نمی‌بلعد.

- **تلگرام.** اگر خروجی چند بار پشت سر هم قطع و وصل شود، آخرین پیام در گفت‌وگو اکنون وضعیت واقعی را می‌گوید. ربات پیکربندی کلاینتی را که در نامش `<` دارد می‌فرستد، بلافاصله پس از خاموش کردن کنترل دیگر فرمان‌ها را اجرا نمی‌کند، و پس از پاسخ ناقص تلگرام از کار نمی‌افتد.

- **اصلاحات رابط.** پیام‌های خطا دیگر زیر پنجرهٔ باز پنهان نمی‌شوند؛ گزینهٔ تازهٔ فیلتر DNS ذخیره می‌شود؛ دکمه‌های پایین‌تر در زبانهٔ «سرور» دیگر تغییرات بالاتر را بی‌صدا دور نمی‌ریزند؛ اگر پنل درست پس از ورود پاسخ ندهد، صفحه دیگر خالی نمی‌ماند؛ پراکسی به شکل `نشانی:درگاه` پذیرفته می‌شود؛ Enter دوم دو کلاینت نمی‌سازد؛ روی گوشی، وقتی خروجی‌ای از کار افتاده، نام کلاینت‌ها فشرده نمی‌شود. متن‌ها در هر چهار زبان روشن‌ترند.

- **سبک‌تر با کلاینت‌های زیاد.** صفحه هر چند ثانیه حدود یک‌بیستم دادهٔ کمتری دریافت می‌کند و فهرست کلاینت‌ها را روی گوشی‌های کند سریع‌تر می‌کشد؛ سرور دیگر وقتی چیزی تغییر نکرده، فایل شمارنده‌های ترافیک را هر دقیقه از نو نمی‌نویسد.

</div>

<div dir="rtl">

**بازگشت به 1.20.0.** نسخهٔ 1.21.0 متن فهرست‌هایی را که خودتان وارد کرده‌اید (شبکه‌ها و دامنه‌ها) در فایل‌های جداگانه نگه می‌دارد، نه در <bdi>`state.json`</bdi>. نسخهٔ 1.20.0 روی این فایل‌ها این فهرست‌ها را خالی نشان می‌دهد (قوانین آن‌ها با آخرین نسخهٔ ساخته‌شدهٔ فهرست کار می‌کنند)؛ برای برگرداندن متن‌ها، نسخهٔ پشتیبان را بازیابی کنید (**سیستم ← پشتیبان**): نسخه‌های پشتیبان همچنان متن‌ها را دارند. نسخهٔ پشتیبانی که در 1.21.0 ساخته شده، فقط وقتی در 1.20.0 پذیرفته می‌شود که قانون دامنهٔ تازه (به خروجی AmneziaWG، «مستقیم» یا «مسدود») نداشته باشد؛ نسخهٔ پشتیبانِ پیش از به‌روزرسانی همیشه پذیرفته می‌شود. برای بازگشت، روی سرور اجرا کنید: <bdi>`AWGR_SRC_URL=https://github.com/r-slashslash/AWG-Router/releases/download/v1.20.0/awg-router.tar.gz awg-router update`</bdi>. در 1.20.0 روی چنین فهرستی «به‌روزرسانی اکنون» را نزنید: فهرست را از متن خالی می‌سازد و قوانینش بی‌نشانی می‌مانند (1.21.0 هنگام بازگشت این فهرست‌ها را دوباره از متنشان می‌سازد). نسخهٔ 1.20.0 فایل قوانین «پیش از پنل» (<bdi>`awgr-hold-awg0.nft`</bdi> کنار پیکربندی سرور) را نه به کار می‌برد و نه پاک می‌کند؛ اگر روی 1.20.0 می‌مانید، می‌توانید آن را پاک کنید.
