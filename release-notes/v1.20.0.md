## What's changed

- **AmneziaWG engine: amneziawg-go or the kernel module.** The kernel module encrypts inside the Linux kernel: several times less CPU than amneziawg-go, which matters on a small VPS with many clients or in a cascade. The new **Server → AmneziaWG engine** block shows what the server runs on and which module is loaded, explains when the module is worth it, and lets tunnels to exits run on it. To install the module, run `sudo awg-router install-kernel` on the server (Ubuntu 22.04+ or Debian 12+), then press **Restart the AWG server**. If the module can't start a tunnel, the panel moves it back to amneziawg-go by itself, and it warns when a module too old for AWG 3.1 is loaded. Nothing changes until you choose to: amneziawg-go stays the default. Thanks to @paris19891 (#24).

- **CPU and memory in the status line.** Next to the client count the panel now shows how loaded the server's processor and memory are. 90% and above is highlighted; hover for the load average and how much memory is in use.

- **The AWG server comes back by itself.** If the AmneziaWG server's interface disappears while its container keeps running — for example, the kernel killed `amneziawg-go` when memory ran out, and clients stayed offline until someone restarted it by hand — the panel now restarts the server by itself after half a minute and tells you in Telegram. In host mode the server's service is restarted the same way. To do it by hand: **Server → Restart the AWG server**.

- **Telegram: server resources.** A new checkbox in the notification settings: memory above 90% or CPU above 95% for 5 minutes, and when it is back to normal.

- **The panel over IPv6.** The panel now opens over IPv6 as well as IPv4. An IPv6 address in **Server public address** now works the way this one field is meant to: the panel opens at it, gets its Let's Encrypt certificate for it, and clients connect to it unless you pick another address in **Address in configs**. The field's hint now explains this. The certificate now covers both the server's IPv4 and IPv6 addresses, so the panel opens without a warning at either. If Let's Encrypt can't check the second one (for example, port 80 is closed over it), the certificate covers the main address. Failed sign-ins from IPv6 are counted per /64 network, so changing the address does not get around the lockout. If your server's firewall has separate rules for IPv6, open the panel port there. Thanks to @paris19891 (#20).

- **Let's Encrypt through a web server on port 80 works.** Since 1.14.0 the panel put its test file in the wrong folder, so validation through nginx, Apache or Caddy always failed with HTTP 404 and was rolled back. If port 80 on your server is taken by a web server, open **System → Domain and certificate** after the update and set up the validation again. Thanks to @xiaomiiraqly-alt (#21).

- **Exits at an IPv6 address.** In the AmneziaVPN container mode Docker gives the container no IPv6 by default, so such an exit just showed "no connection". Now it says why and what to do: turn on IPv6 in Docker (README, "Limitations") or give the exit an IPv4 address or a domain with an A record. If IPv6 in Docker is already on, nothing changes. Thanks to @paris19891 (#20).

- **A domain in client configs.** With a panel domain, the installer now asks which address client configs use: the domain keeps configs working if the server's IP changes. Answer it without a prompt with `AWGR_CLIENT_DOMAIN=yes` or `no`. The installer no longer warns that the domain points elsewhere when `PUBLIC_HOST` is a domain, and `--reconfigure` asks again (Enter keeps what you had). Saving the **Server** tab no longer turns the `.env` address into a panel setting that silently overrode `.env`. Thanks to @koo-pub (#22, #23).

- **Smaller fixes.** Restoring a backup from another server no longer brings back the old server's address when this one uses the address from `.env`: before, client configs, the panel link and the certificate got the old IP. An exit whose fallbacks lead back to itself (A → B → A) is now refused: with all of them down, clients would have been left without a connection. The certificate keeps renewing after an unexpected error instead of stopping until the panel restarts.

## Что изменилось

- **Движок AmneziaWG: amneziawg-go или модуль ядра.** Модуль ядра шифрует внутри ядра Linux: процессора уходит в разы меньше, чем у amneziawg-go, что важно на слабом VPS с многими клиентами или в каскаде. Новый блок **«Сервер» → «Движок AmneziaWG»** показывает, чем работает сервер и какой модуль загружен, объясняет, когда модуль нужен, и позволяет перевести на него туннели к выходам. Чтобы поставить модуль, выполните на сервере `sudo awg-router install-kernel` (Ubuntu 22.04+ или Debian 12+) и нажмите **«Перезапустить сервер AWG»**. Если модуль не запустит туннель, панель сама вернёт его на amneziawg-go, а если загружен модуль, слишком старый для AWG 3.1, — предупредит. Пока вы сами не выберете, ничего не меняется: по умолчанию остаётся amneziawg-go. Спасибо @paris19891 (#24).

- **Процессор и память в строке состояния.** Рядом с числом клиентов панель теперь показывает, насколько загружены процессор и память сервера. От 90 % значение выделяется цветом; в подсказке — средняя нагрузка и сколько памяти занято.

- **Сервер AWG поднимается сам.** Если у сервера AmneziaWG пропал интерфейс, а контейнер продолжает работать (например, ядро завершило `amneziawg-go` из-за нехватки памяти, и клиенты были без связи, пока сервер не перезапустили вручную), панель теперь сама перезапускает сервер через полминуты и сообщает об этом в Telegram. В режиме хоста так же перезапускается служба сервера. Вручную: **«Сервер» → «Перезапустить сервер AWG»**.

- **Telegram: ресурсы сервера.** Новая галочка в настройках уведомлений: память занята больше чем на 90% или процессор больше чем на 95% дольше 5 минут, и когда всё вернулось в норму.

- **Панель по IPv6.** Панель теперь открывается и по IPv6, а не только по IPv4. Адрес IPv6 во **«Внешнем адресе сервера»** теперь работает так, как задумано у этого одного поля: по нему открывается панель, на него она получает сертификат Let's Encrypt, и к нему же подключаются клиенты, если в **«Адрес в конфигах»** не выбран другой адрес. Подсказка у поля теперь это объясняет. Сертификат теперь выписывается сразу на IPv4 и IPv6 сервера, так что панель открывается без предупреждения по любому из них. Если Let's Encrypt не может проверить второй адрес (например, порт 80 по нему закрыт), сертификат будет на основной. Неудачные входы с IPv6 считаются по сети /64, поэтому сменой адреса блокировку не обойти. Если у файрвола сервера отдельные правила для IPv6, откройте там порт панели. Спасибо @paris19891 (#20).

- **Let's Encrypt через веб-сервер на порту 80 работает.** С версии 1.14.0 панель клала проверочный файл не в ту папку, поэтому проверка через nginx, Apache или Caddy всегда заканчивалась ошибкой HTTP 404 и откатывалась. Если порт 80 на вашем сервере занят веб-сервером, после обновления откройте **«Система» → «Домен и сертификат»** и настройте проверку ещё раз. Спасибо @xiaomiiraqly-alt (#21).

- **Выходы с адресом IPv6.** В режиме контейнера AmneziaVPN Docker по умолчанию не даёт контейнеру IPv6, и такой выход просто показывал «нет связи». Теперь он пишет причину и что делать: включить IPv6 в Docker (README, «Ограничения») или указать у выхода IPv4-адрес либо домен с записью A. Если IPv6 в Docker уже включён, ничего не меняется. Спасибо @paris19891 (#20).

- **Домен в конфигах клиентов.** Если задан домен панели, установщик теперь спрашивает, какой адрес ставить в конфиги клиентов: с доменом конфиги продолжат работать, если у сервера сменится IP. Ответить без вопроса можно через `AWGR_CLIENT_DOMAIN=yes` или `no`. Установщик больше не пишет, что домен указывает на другой сервер, когда `PUBLIC_HOST` — домен, а `--reconfigure` спрашивает снова (Enter оставляет как было). Сохранение вкладки **«Сервер»** больше не превращает адрес из `.env` в настройку панели, которая молча перекрывала `.env`. Спасибо @koo-pub (#22, #23).

- **Мелкие исправления.** Восстановление копии с другого сервера больше не возвращает адрес старого сервера, когда этот берёт адрес из `.env`: раньше конфиги клиентов, ссылка на панель и сертификат получали старый IP. Выход, у которого резервы по цепочке возвращаются к нему же (A → B → A), теперь не сохраняется: когда все они лежат, клиенты остались бы без связи. Сертификат продолжает продлеваться после неожиданной ошибки, а не перестаёт до перезапуска панели.

## 改动

- **AmneziaWG 引擎：amneziawg-go 或内核模块。** 内核模块在 Linux 内核中加密：CPU 占用比 amneziawg-go 低数倍，这在客户端多的低配 VPS 或级联中很重要。新的 **服务器 → AmneziaWG 引擎** 区块显示服务器使用的引擎和已加载的模块，说明何时值得使用模块，并可让通往出口的隧道改用模块。要安装模块，请在服务器上运行 `sudo awg-router install-kernel`（Ubuntu 22.04+ 或 Debian 12+），然后点击 **重启 AWG 服务器**。如果模块无法启动隧道，面板会自动切回 amneziawg-go；如果加载的模块太旧、不支持 AWG 3.1，面板会发出警告。在你自己选择之前什么都不会改变：默认仍是 amneziawg-go。感谢 @paris19891（#24）。

- **状态栏显示 CPU 和内存。** 面板现在在客户端数量旁显示服务器处理器和内存的占用情况。达到 90% 及以上时会高亮显示；悬停可查看平均负载和已用内存。

- **AWG 服务器自动恢复。** 如果 AmneziaWG 服务器的接口消失而容器仍在运行（例如内存不足时内核终止了 `amneziawg-go`，客户端一直断线，直到有人手动重启），面板现在会在半分钟后自动重启服务器并通过 Telegram 通知你。主机模式下服务器服务也会以同样方式重启。手动重启：**服务器 → 重启 AWG 服务器**。

- **Telegram：服务器资源。** 通知设置中新增一个选项：内存超过 90% 或 CPU 超过 95% 持续 5 分钟，以及恢复正常时。

- **面板支持 IPv6。** 面板现在除 IPv4 外也可通过 IPv6 打开。**服务器公网地址** 中填写 IPv6 地址现在会按这个字段的本意工作：面板通过它打开，为它申请 Let's Encrypt 证书，客户端也连接到它，除非你在 **配置中的地址** 中另选地址。字段提示现在说明了这一点。证书现在同时签发给服务器的 IPv4 和 IPv6 地址，通过任一地址打开面板都不会出现警告。如果 Let's Encrypt 无法验证第二个地址（例如该地址的 80 端口被关闭），证书只签发给主地址。来自 IPv6 的登录失败按 /64 网络计数，更换地址无法绕过锁定。如果服务器防火墙对 IPv6 有单独的规则，请在其中开放面板端口。感谢 @paris19891（#20）。

- **通过 80 端口上的 Web 服务器进行 Let's Encrypt 验证现已可用。** 从 1.14.0 起，面板把验证文件放错了目录，所以通过 nginx、Apache 或 Caddy 的验证总是以 HTTP 404 失败并被回滚。如果服务器的 80 端口被 Web 服务器占用，更新后请打开 **系统 → 域名和证书**，重新设置验证。感谢 @xiaomiiraqly-alt（#21）。

- **使用 IPv6 地址的出口。** 在 AmneziaVPN 容器模式下，Docker 默认不给容器分配 IPv6，这样的出口只会显示“无连接”。现在它会说明原因和解决办法：在 Docker 中启用 IPv6（见 README“限制”一节），或为出口改用 IPv4 地址或带 A 记录的域名。如果 Docker 已启用 IPv6，则一切照旧。感谢 @paris19891（#20）。

- **客户端配置中使用域名。** 设置了面板域名时，安装程序现在会询问客户端配置使用哪个地址：使用域名时，即使服务器 IP 变化，配置也能继续使用。可通过 `AWGR_CLIENT_DOMAIN=yes` 或 `no` 直接回答。当 `PUBLIC_HOST` 是域名时，安装程序不再误报域名指向其他服务器，`--reconfigure` 会再次询问（按 Enter 保持原样）。保存 **服务器** 选项卡不再把 `.env` 中的地址变成悄悄覆盖 `.env` 的面板设置。感谢 @koo-pub（#22、#23）。

- **小修复。** 从另一台服务器的备份恢复时，如果本服务器使用 `.env` 中的地址，不再带回旧服务器的地址：以前客户端配置、面板链接和证书都会变成旧 IP。出口的备用沿链条又回到它自己（A → B → A）时，现在无法保存：它们全部断开时，客户端将无法连接。证书在意外错误后会继续续期，而不是在面板重启前一直停止。

## تغییرها

- **موتور AmneziaWG: ‏amneziawg-go یا ماژول هسته.** ماژول هسته درون هستهٔ لینوکس رمزنگاری می‌کند: چند برابر پردازندهٔ کمتر از amneziawg-go، که روی VPS ضعیف با کلاینت‌های زیاد یا در آبشار مهم است. بخش تازهٔ **سرور ← موتور AmneziaWG** نشان می‌دهد سرور با چه چیزی کار می‌کند و کدام ماژول بارگذاری شده، توضیح می‌دهد کی ماژول ارزشش را دارد و اجازه می‌دهد تونل‌ها به خروجی‌ها روی آن بروند. برای نصب ماژول روی سرور <bdi>`sudo awg-router install-kernel`</bdi> را اجرا کنید (اوبونتو 22.04 یا جدیدتر، یا دبیان 12 یا جدیدتر) و **راه‌اندازی دوبارهٔ سرور AWG** را بزنید. اگر ماژول نتواند تونلی را راه بیندازد، پنل خودش آن را به amneziawg-go برمی‌گرداند و اگر ماژولی بارگذاری شده باشد که برای AWG 3.1 قدیمی است، هشدار می‌دهد. تا خودتان انتخاب نکنید چیزی تغییر نمی‌کند: پیش‌فرض همان amneziawg-go است. سپاس از <bdi>@paris19891</bdi> (<bdi>#24</bdi>).

- **پردازنده و حافظه در نوار وضعیت.** پنل اکنون کنار تعداد کلاینت‌ها نشان می‌دهد پردازنده و حافظهٔ سرور چقدر درگیرند. از <bdi>90%</bdi> به بالا رنگی می‌شود؛ راهنمای روی آن میانگین بار و مقدار حافظهٔ مصرفی را نشان می‌دهد.

- **سرور AWG خودش برمی‌گردد.** اگر رابط سرور AmneziaWG از بین برود ولی کانتینر همچنان کار کند (مثلاً هسته به دلیل کمبود حافظه `amneziawg-go` را ببندد و کلاینت‌ها تا راه‌اندازی دستی قطع بمانند)، پنل اکنون پس از نیم دقیقه خودش سرور را دوباره راه‌اندازی می‌کند و در تلگرام خبر می‌دهد. در حالت میزبان هم سرویس سرور به همین شکل دوباره راه‌اندازی می‌شود. دستی: **سرور ← راه‌اندازی دوبارهٔ سرور AWG**.

- **تلگرام: منابع سرور.** گزینهٔ تازه در تنظیمات اعلان‌ها: حافظه بیش از <bdi>90%</bdi> یا پردازنده بیش از <bdi>95%</bdi> به مدت ۵ دقیقه، و وقتی دوباره عادی شود.

- **پنل با IPv6.** پنل اکنون علاوه بر IPv4 با IPv6 هم باز می‌شود. نشانی IPv6 در **آدرس عمومی سرور** اکنون همان‌طور کار می‌کند که این یک فیلد برایش طراحی شده است: پنل با آن باز می‌شود، گواهی Let's Encrypt را برای آن می‌گیرد و کلاینت‌ها هم به آن وصل می‌شوند، مگر اینکه در **آدرس در پیکربندی‌ها** نشانی دیگری انتخاب کنید. راهنمای فیلد اکنون همین را توضیح می‌دهد. گواهی اکنون هم برای IPv4 و هم برای IPv6 سرور صادر می‌شود، پس پنل با هر دو بدون هشدار باز می‌شود. اگر Let's Encrypt نتواند نشانی دوم را بررسی کند (مثلاً درگاه 80 روی آن بسته باشد)، گواهی فقط برای نشانی اصلی است. ورودهای ناموفق از IPv6 به ازای هر شبکهٔ <bdi>/64</bdi> شمرده می‌شوند، پس با عوض کردن نشانی نمی‌توان از قفل گذشت. اگر دیوارهٔ آتش سرور برای IPv6 قانون‌های جداگانه دارد، درگاه پنل را آنجا باز کنید. سپاس از <bdi>@paris19891</bdi> (<bdi>#20</bdi>).

- **اعتبارسنجی Let's Encrypt از راه وب‌سرور روی درگاه 80 کار می‌کند.** از نسخهٔ 1.14.0 پنل فایل آزمایشی را در پوشهٔ اشتباه می‌گذاشت، برای همین اعتبارسنجی از راه nginx، Apache یا Caddy همیشه با خطای <bdi>HTTP 404</bdi> شکست می‌خورد و برگردانده می‌شد. اگر درگاه 80 سرور شما را وب‌سرور گرفته است، پس از به‌روزرسانی **سیستم ← دامنه و گواهی** را باز کنید و اعتبارسنجی را دوباره تنظیم کنید. سپاس از <bdi>@xiaomiiraqly-alt</bdi> (<bdi>#21</bdi>).

- **خروجی با نشانی IPv6.** در حالت کانتینر AmneziaVPN، Docker به‌طور پیش‌فرض به کانتینر IPv6 نمی‌دهد و چنین خروجی‌ای فقط «بدون اتصال» نشان می‌داد. اکنون علت و راه‌حل را می‌گوید: IPv6 را در Docker روشن کنید (README، بخش «محدودیت‌ها») یا برای خروجی نشانی IPv4 یا دامنه‌ای با رکورد A بدهید. اگر IPv6 در Docker از قبل روشن است، چیزی تغییر نمی‌کند. سپاس از <bdi>@paris19891</bdi> (<bdi>#20</bdi>).

- **دامنه در پیکربندی کلاینت‌ها.** اگر دامنهٔ پنل تعیین شده باشد، نصب‌کننده اکنون می‌پرسد کدام نشانی در پیکربندی کلاینت‌ها بیاید: با دامنه، اگر IP سرور عوض شود پیکربندی‌ها کار می‌کنند. بدون پرسش هم می‌توان با <bdi>`AWGR_CLIENT_DOMAIN=yes`</bdi> یا <bdi>`no`</bdi> پاسخ داد. وقتی `PUBLIC_HOST` دامنه است، نصب‌کننده دیگر به اشتباه نمی‌گوید دامنه به سرور دیگری اشاره می‌کند و <bdi>`--reconfigure`</bdi> دوباره می‌پرسد (Enter همان قبلی را نگه می‌دارد). ذخیرهٔ زبانهٔ **سرور** دیگر نشانی `.env` را به تنظیم پنل تبدیل نمی‌کند که بی‌صدا `.env` را کنار می‌گذاشت. سپاس از <bdi>@koo-pub</bdi> (<bdi>#22</bdi>، <bdi>#23</bdi>).

- **اصلاح‌های کوچک.** بازگردانی نسخهٔ پشتیبان از سرور دیگر، وقتی این سرور نشانی را از `.env` می‌گیرد، دیگر نشانی سرور قدیمی را برنمی‌گرداند: پیش‌تر پیکربندی کلاینت‌ها، پیوند پنل و گواهی IP قدیمی را می‌گرفتند. خروجی‌ای که پشتیبان‌هایش در زنجیره به خودش برمی‌گردند (<bdi>A → B → A</bdi>) اکنون ذخیره نمی‌شود: وقتی همه از کار بیفتند، کلاینت‌ها بی‌اتصال می‌ماندند. گواهی پس از یک خطای غیرمنتظره همچنان تمدید می‌شود و تا راه‌اندازی دوبارهٔ پنل متوقف نمی‌ماند.
