## What's changed

- **Encrypted DNS on the server.** "DNS on the server" now encrypts queries to the servers from the "DNS" field: **DoH** (DNS over HTTPS, port 443) by default, or **DoT** (port 853), or none — the new setting **DNS query encryption** under it. Neither the ISP of this server nor the ISP of the exit can see which sites clients open or spoof the answers: the server's certificate is checked. Queries still go through each client's own exit, so CDNs return nodes in the right country. Use servers that support encryption, for example 1.1.1.1 and 8.8.8.8 (also 1.0.0.1, 8.8.4.4, 9.9.9.9, 149.112.112.112). If the encrypted channel is down, plain DNS is not used: clients ask the second DNS from their config, and the panel and the bot show "DNS servers don't answer". If you turned "DNS on the server" on in 1.15.0, it stays unencrypted until you choose DoH or DoT.
- **Bot: Server › Status** shows the DNS encryption mode and a warning when the DNS servers don't answer.
- **More precise description.** The hint and README said that with AmneziaDNS the local ISP can spoof answers. AmneziaDNS encrypts its queries, so the ISP can only block the connection; the real catch is that the answers are fetched from the entry country.

## Что изменилось

- **Шифрование DNS на сервере.** «DNS на сервере» теперь шифрует запросы к серверам из поля «DNS»: по умолчанию **DoH** (DNS поверх HTTPS, порт 443), можно **DoT** (порт 853) или без шифрования — новая настройка **«Шифрование запросов DNS»** под ним. Указывайте серверы с поддержкой шифрования, например 1.1.1.1 и 8.8.8.8 (подходят и 1.0.0.1, 8.8.4.4, 9.9.9.9, 149.112.112.112). Если зашифрованный канал недоступен, открытый DNS не используется: клиенты спросят второй DNS из конфига, а панель и бот покажут «Серверы DNS не отвечают». Если вы включили «DNS на сервере» в 1.15.0, он остаётся без шифрования, пока вы не выберете DoH или DoT.

## 改动

- **服务器上的 DNS 支持加密。** 「服务器上的 DNS」现在会加密发往「DNS」字段中服务器的查询：默认 **DoH**（基于 HTTPS 的 DNS，443 端口），也可选 **DoT**（853 端口）或不加密——即其下方的新设置 **DNS 查询加密**。这台服务器和出口的运营商都看不到客户端访问了哪些网站，也无法篡改答案：服务器证书会被校验。查询仍经由每个客户端自己的出口，因此 CDN 会返回正确国家的节点。请使用支持加密的服务器，例如 1.1.1.1 和 8.8.8.8（1.0.0.1、8.8.4.4、9.9.9.9、149.112.112.112 也可以）。如果加密通道不可用，不会改用未加密的 DNS：客户端会查询配置中的第二个 DNS，面板和机器人会显示「DNS 服务器无响应」。如果你在 1.15.0 中开启了「服务器上的 DNS」，在你选择 DoH 或 DoT 之前它仍保持不加密。
- **机器人：服务器 › 状态** 会显示 DNS 加密模式，并在 DNS 服务器无响应时给出提示。
- **描述更准确。** 提示和 README 中曾说使用 AmneziaDNS 时本地运营商可以篡改答案。AmneziaDNS 会加密查询，运营商只能屏蔽连接；真正的陷阱在于答案是从入口国家获取的。

## تغییرها

- **رمزگذاری DNS روی سرور.** «DNS روی سرور» اکنون پرسش‌ها به سرورهای فیلد «DNS» را رمزگذاری می‌کند: به‌طور پیش‌فرض **DoH** (DNS روی HTTPS، درگاه 443)، یا **DoT** (درگاه 853)، یا بدون رمزگذاری — تنظیم تازهٔ **رمزگذاری پرسش‌های DNS** زیر آن. نه ارائه‌دهندهٔ این سرور و نه ارائه‌دهندهٔ خروجی نمی‌بینند کلاینت‌ها کدام سایت‌ها را باز می‌کنند و نمی‌توانند پاسخ‌ها را جعل کنند: گواهی سرور بررسی می‌شود. پرسش‌ها همچنان از خروجی خود هر کلاینت می‌روند، پس CDNها گره‌های کشور درست را می‌دهند. سرورهایی بگذارید که رمزگذاری را پشتیبانی می‌کنند، مثلاً 1.1.1.1 و 8.8.8.8 (1.0.0.1، 8.8.4.4، 9.9.9.9 و 149.112.112.112 هم مناسب‌اند). اگر کانال رمزگذاری‌شده در دسترس نباشد، DNS بدون رمز استفاده نمی‌شود: کلاینت‌ها DNS دوم پیکربندی را می‌پرسند و پنل و ربات «سرورهای DNS پاسخ نمی‌دهند» را نشان می‌دهند. اگر «DNS روی سرور» را در 1.15.0 روشن کرده‌اید، تا وقتی DoH یا DoT را انتخاب نکنید بدون رمزگذاری می‌ماند.
- **ربات: سرور › وضعیت** حالت رمزگذاری DNS را نشان می‌دهد و اگر سرورهای DNS پاسخ ندهند هشدار می‌دهد.
- **توضیح دقیق‌تر.** در راهنما و README آمده بود که با AmneziaDNS ارائه‌دهندهٔ محلی می‌تواند پاسخ‌ها را جعل کند. AmneziaDNS پرسش‌ها را رمزگذاری می‌کند، پس ارائه‌دهنده فقط می‌تواند اتصال را مسدود کند؛ دام واقعی این است که پاسخ‌ها از کشور ورودی گرفته می‌شوند.
