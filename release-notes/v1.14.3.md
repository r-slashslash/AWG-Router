## What's changed

- **Exit with a domain name in Endpoint.** If an exit's config had `Endpoint = name:port` instead of an IP address, the tunnel never came up: `awg setconf` waited 30 seconds and failed, and every retry did the same. The cause was DNS: the command runs in the Amnezia container's network, but the resolver settings are the panel's, and on hosts with systemd-resolved they point to 127.0.0.53, where nobody listens there. The panel now resolves the name itself, before the tunnel is created. The config keeps the name, so the name is resolved again each time the tunnel is brought up: change the DNS record and the exit moves to the new server at the next restart of the tunnel. If the name can't be resolved, the exit shows a clear error. Thanks to @LCF30 for the detailed report.
- **Exit check.** The check could show "external IP unknown" for the same reason; it now gets the addresses of its test sites from the panel.

## Update

**System → Update** in the panel (since 1.4.0), or on the server:

    awg-router update

New install (Ubuntu or Debian, as root):

## Что изменилось

- **Выход с доменным именем в Endpoint.** Если в конфиге выхода вместо IP-адреса стояло `Endpoint = имя:порт`, туннель не поднимался: `awg setconf` ждал 30 секунд и завершался ошибкой, повторные попытки давали то же. Причина в DNS: команда выполняется в сети контейнера Amnezia, а настройки резолвера остаются от панели, и на серверах с systemd-resolved они указывают на 127.0.0.53, где в той сети никто не слушает. Теперь панель сама разбирает имя до создания туннеля. В конфиге имя остаётся, поэтому оно разбирается заново при каждом подъёме туннеля: измените запись DNS — и выход перейдёт на новый сервер при следующем перезапуске туннеля. Если имя разобрать не удалось, у выхода появляется понятная ошибка. Спасибо @LCF30 за подробный отчёт.
- **Проверка выхода.** Из-за той же причины проверка могла показывать «внешний IP не определён»; теперь адреса своих сайтов для проверки она получает от панели.

## 改动

- **Endpoint 为域名的出口。** 如果出口配置中的 Endpoint 写的是 `name:port` 而不是 IP 地址，隧道就无法建立：`awg setconf` 等待 30 秒后报错，之后的重试结果相同。原因在于 DNS：该命令在 Amnezia 容器的网络中运行，但解析器设置仍是面板的；在使用 systemd-resolved 的服务器上，它指向 127.0.0.53，而那个网络里没有任何程序监听该地址。现在面板在创建隧道之前自己解析域名。配置中仍保留域名，因此每次启动隧道时都会重新解析：修改 DNS 记录后，出口会在隧道下次重启时切换到新服务器。如果无法解析，出口会显示明确的错误。感谢 @LCF30 提供详细的报告。
- **出口检测。** 由于同样的原因，检测可能显示「无法确定外部 IP」；现在检测所用网站的地址由面板提供。

## تغییرها

- **خروجی با نام دامنه در Endpoint.** اگر در پیکربندی خروجی به‌جای نشانی IP مقدار `Endpoint = name:port` بود، تونل بالا نمی‌آمد: `awg setconf` سی ثانیه منتظر می‌ماند و با خطا تمام می‌شد و تلاش‌های بعدی هم همین نتیجه را داشتند. علت DNS بود: این فرمان در شبکهٔ کانتینر Amnezia اجرا می‌شود، اما تنظیمات resolver همان تنظیمات پنل است و روی سرورهای دارای systemd-resolved به 127.0.0.53 اشاره می‌کند، جایی که در آن شبکه کسی گوش نمی‌دهد. اکنون پنل پیش از ساخت تونل خودش نام را به نشانی تبدیل می‌کند. نام در پیکربندی می‌ماند و بنابراین در هر بار بالا آمدن تونل دوباره تبدیل می‌شود: رکورد DNS را عوض کنید تا خروجی در راه‌اندازی مجدد بعدی تونل به سرور تازه برود. اگر نام تبدیل نشود، خروجی خطای روشنی نشان می‌دهد. از @LCF30 برای گزارش دقیقش سپاسگزاریم.
- **بررسی خروجی.** به همین دلیل بررسی ممکن بود «IP خارجی نامشخص» نشان دهد؛ اکنون نشانی سایت‌های آزمایشی را از پنل می‌گیرد.
